# 状態保存と復元

[English](SNAPSHOTS.en.md)

同じPythonセッション内で状態を控え、試した計算を元へ戻したり、同じ状態から条件を変えて計算したりするための機能です。ディスクに保存して別のジョブで再開する方法は[保存・再開ガイド](CHECKPOINTING.md)を参照してください。

`state.snapshot()` は変更できない `StateSnapshot` オブジェクトを返します。
`state.restore(token)` は最後に成功した計算状態を置き換え、`None`を返します。
固定dt・メモリ上の保存状態で、最後に成功した計算時刻を進めません。軽い部品は配列コピーで復元します。
プロセス分離TDDFTは監査済みソルバーを別途起動し、一時ファイルを使って履歴を再生します。
ソルバーのビルドやMPI通信は行いません。

## 保存する履歴

| 状態 | 保存する時間発展の履歴 |
|---|---|
| `TDDFTState`（プロセス分離） | 初期A・電流、受理済みA・電流の履歴、ステップ数 |
| `LDState` | 極ごとのP/J、直前のE、ステップ数 |
| `SBEState` | 密度行列、直前のA/c、内部の物質電流、ステップ数 |
| `Transverse`の状態 | A、ステップ数 |
| `Longitudinal`の状態 | A、2時刻分の誘起A、ステップ数 |
| `ThinFilm`の状態 | A、反射A、ステップ数 |
| `Multiscale1D`の状態 | マクロ点A、境界セルを含む全格子の旧・現・新A、格子電流、ステップ数 |

スキーマ・パッケージ版・時刻・互換条件・データ整合性も記録します。
元のモデルへの参照を保持するため、不要なトークンは破棄してください。
時間発展配列を複製するので、必要メモリは状態サイズと保存数に応じて増えます。
圧縮やメモリ上限の強制はありません。

## 互換条件と独立性

元の状態、または**同じモデルオブジェクト**から作った状態に復元できます。
dt・開始時刻が一致することが必要です。LDは初期Eの設定も一致させます。
場は最大ステップ数、形状・境界、サンプル済みの外場・入射波も一致させます。
同じ係数でも別々に構築したモデルは、この初版では拒否します。
関数で駆動波形を渡す場合、新規の場状態を作る際に評価します。同じ関数・モデルでも
サンプル値が異なれば復元を拒否します。

検証と配列確保をすべて終えてから状態を置き換えます。不正な復元は `SnapshotError` を
送出し、受理済み履歴を保持します。保存内容は不変のバイト列で、復元先には新しい配列を作ります。
一方の状態のstep／restoreは、別の状態や保存済みトークンを書き換えません。
同じ状態オブジェクトへの複数スレッドからの同時呼出しには対応しません。

```python
import numpy as np
from salmonpy.ld import LorentzDrude

model = LorentzDrude(plasma_frequency=1., strength=[1.],
                     resonance=[0.], damping=[0.1])
a = model.new_state(dt=0.02)
a.step([0.1, 0., 0.])
saved = a.snapshot()
expected_p, expected_j = a.step([0.2, 0., 0.])
a.restore(saved)
p, j = a.step([0.2, 0., 0.])
np.testing.assert_array_equal(j, expected_j)

b = model.new_state(dt=0.02)
b.restore(saved)             # saved.timeで独立した分岐を作る
b.step([-0.1, 0., 0.])      # aとsavedは変化しない
```

`python -m salmonpy.examples.snapshot_restore` でLD・SBE・4種類の場を実行できます。
導入済みLD/SBE計算ルーチンが必要ですが、SALMON本体は不要です。
例は同じ環境での再実行の完全一致を検査します。異なる環境でのビット一致や
物理的収束を保証するものではなく、科学計算の回帰比較では従来の許容差を使います。

## プロセス分離TDDFTの履歴再生

`TDDFTInitialState.new_state`で作った状態に`saved = state.snapshot()`、
`state.restore(saved)`を使えます。同一の初期モデルオブジェクト・dt・初期A・
最大ステップ数・実行ファイルSHA256・スレッド数が必要です。閉じた状態では拒否します。
初期モデルを閉じた後も、既存状態は共有する保存用バンドルを保持して復元できます。
保存用は1組だけで、各ワーカーの作業用コピーは独立しています。N個の状態では、
入力元・保存済み出力を除いてN+1組です。復元の検証中は作業用がもう1組増えます。
初期モデルを閉じると新規状態は作れず、最後の状態を閉じると保存用も削除します。
起動・復元のたびにコピー後の全ファイルをハッシュ照合してからワーカーを開始します。
作業用ファイルの変更は保存用や他のワーカーへ伝わりません。

別ワーカーで全受理済みAを再生し、初期電流と各端点の物質電流を
rtol=1e-12、atol=1e-14で照合してから切り替えます。失敗時は`SnapshotError`を返し、
元のワーカーと最後に成功した計算状態を保持します。復元後は実際に再生した電流を使います。
出力ファイルも再生成するため、後の`finish()`は復元後の分岐を保存します。
破棄した試行分岐の出力は混ぜません。

保存メモリは保存時点のステップ数に比例します。復元は初期化と全履歴の計算をやり直し、
検証中は2ワーカーと各一時ファイルが共存します。波動関数そのものは保存せず、
Python終了後の再開には使えません。同一環境・1スレッドの回帰試験ではビット一致を検査しますが、
異機種・並列でのビット一致は保証しません。結合する場も同じ時刻へ戻してください。

## TDDFTのディスク保存と再開

```python
# stateは既存のTDDFTState。新しい保存先に、受理済み履歴を保存します。
state.save_checkpoint('checkpoint-0005')

# 別のPythonプロセスで、同じ初期バンドルと監査済み実行ファイルを明示します。
from salmonpy.tddft import TDDFTInitialState
with TDDFTInitialState.from_salmon(
        'existing-initial-bundle', 'rt.inp', executable=engine,
        max_steps=1000, threads=1) as model:
    with model.new_state(dt=0.02) as resumed:
        resumed.restore_checkpoint('checkpoint-0005')
        current = resumed.step([0.1, 0., 0.])
```

`save_checkpoint(directory)`、`restore_checkpoint(directory, max_bytes=None)`は
`TDDFTState`専用で、成功時は`None`を返します。保存先は新規ディレクトリに限り、
既存先を上書きしません。元の入力バンドルと所有している初期バンドルの内側にも保存できません。
ディスク版はモデルオブジェクトが別でも、内容が一致すれば復元できます。
パッケージ版・入力・全初期ファイルのSHA256・実行ファイルSHA256・dt・初期A・
最大ステップ数・スレッド数が一致しなければ、元の状態を変更せず拒否します。
チェックポイントから実行ファイルや初期モデルを自動取得・構築しません。

形式はZarr v3の無圧縮・little-endian float64で、A／電流の履歴を時間方向に分割し、
メタデータと各チャンクのSHA256を`manifest.json`に記録します。
初期GS・擬ポテンシャルの本体は複製せず、初期ファイル名とハッシュのみ参照します。
そのため既存の初期バンドルを別途保持する必要があります。履歴は物質電流Jで保存し、
公開の`current`は従来どおり電荷電流jを返します。Zarrライブラリの追加導入は不要です。

保存途中の通常の例外では新規保存先を片付けます。強制終了で残った不完全な保存先は
読込み時に拒否します。停電時の永続性、並行書込み、読込み中の外部編集は保証しません。
既定の上限は、復元先の最大ステップ数×48バイトに、チャンク端の余白・固定ベクトル・
メタデータ・ハッシュ一覧を加えた形式上の最大量から計算します。マシン共通の固定値ではありません。
`max_bytes`を指定すると、その利用者予算も保存ファイル総量と復号配列サイズに適用します。
読込みに必要なファイルとディレクトリは形式から求め、余分な項目は拒否します。
Pythonの全メモリ、配列コピー、再生中の2ワーカー、
初期GSのメモリを含む上限ではありません。ファイル検証後も既存の全履歴再生を行うため、
復元時間はステップ数に比例します。再生失敗時も元のワーカーを保持します。

同一環境・1スレッドで、別Pythonプロセスから復元後の20ステップがビット一致する
合成入力の回帰試験を実施しています。収束済みGSの物理検証とは区別します。
場を結合している場合は、場の状態も同じ最後に成功した計算時刻へ戻す必要があります。

## 対象外

引き継ぎ指示書のZarr GSアーカイブ、出力NPZ、異なる版にまたがる再開、
C ABI、可変dtの実装ではありません。トークンをシリアライズ・編集したり、出力アーカイブを
restoreへ渡したりしません。公開メタデータ `kind`、`schema`、`version`、`step_index`、`time` は
診断用です。非公開フィールドは編集可能なチェックポイント仕様ではありません。

Pythonと同じプロセスで実行するTDDFT、計算処理E/H FDTD、MPIセッションにはこのAPIを追加していません。
呼び出し元プログラムが対象部品を手動で結合する場合、**同じ受理済み結合時刻で場と物質の両方**を保存・復元します。
部品をまたぐ自動トランザクションはありません。単一状態の原子的な復元をMPI全体の
巻き戻しと読み替えません。`couple()`は引き続き自身で状態を生成・解放します。
可変dt・サブサイクル・計算処理TDDFTの再入可能化は別作業です。基本はtransverseのA駆動です。

SBEは計算処理モデル・密度をハンドルに保持し、snapshot書出しと原子的復元の仕様を維持します。
close/GCとメモリのトレードオフは[SBEの状態管理](SBE.md)を参照してください。

LDも計算処理側に履歴を保持し、保存・復元時だけ全極のP/Jを転送します。状態の解放とメモリは [LD.md](LD.md) を参照してください。
