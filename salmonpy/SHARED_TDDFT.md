# 標準TDDFTのPython共有モデル

[English](SHARED_TDDFT.en.md)

`NativeTDDFTBackend.open_model(initial, dt, context)` は `NativeTDDFTModel`
を返します。不変のGS・入力・擬ポテンシャルをモデル単位で読み、作業コピーと計算処理接続も
1つだけ持ちます。`model.new_state(point_id)` ごとに元のGSから独立した電子状態を作ります。
波動関数、密度・XC、A・電流・時刻、出力、保護・復元用状態は各状態が所有します。
point_idは利用者の識別子であり、計算処理ハンドルや物質定義とは別です。

標準handle/model protocol1対応の明示的に構築・検証した計算プログラムを使います。
import時のビルド・ダウンロード・MPI初期化・入力取得はありません。
変更のない検証済み実行物は記録済みSHA256で確認します。呼び出し元プログラムがMPIを管理し、
物質群内の全ランクがメインスレッドから同じ順に呼びます。入力・作業ファイルは変更せず、
work_rootは初期状態のフォルダ外に用意してください。

基本コードは [English](SHARED_TDDFT.en.md) の実行例と共通です。
`provider.prepare(context)` で初期状態を用意し、`backend.open_model(initial, dt, context)`、
`a=model.new_state("film/0")`、`b=model.new_state("film/1")` と作成します。
各 `state.step(A)` でその点の電流jを得ます。
`a.checkpoint(path)` で保存し、新しい状態の `checkpoint(path, restore=True)` で直接復元します。
保存先親フォルダは事前作成し、MPIランクごとに異なる未使用ファイル名を指定します。
復元には同じバイナリ・入力・dt・容量・MPI分割と認証済みファイルが必要です。
単独計算処理ファイルの認証は呼び出し元プログラム側の責任です。通常サンプルの一括保存なら由来検査も行います。
再開時に過去のステップを再計算せず、過去のテキスト出力の連結は行いません。

状態とモデルは明示的にcloseし、その後呼び出し元プログラムのMPIを終了します。
モデルclose後は新しい状態を作れませんが、既存状態は継続できます。
1つの状態のcloseで兄弟状態は終了しません。モデルが開いていれば全状態close後の再作成も可能です。
この既定APIは1プロセスで1モデルを扱います。異なる入力を同じプロセスで順次切り替える場合は
[明示的モデル登録](TDDFT_REGISTRY.md)を使います。並行スレッドには対応しません。

対応範囲は周期系・全k点（対称性縮約なし）・非スピン偏極・固定イオン、
PZ、TB-mBJ（c自動／固定）、Libxc-PZ/PBE、transverseのmiddlepoint伝播です。
**dt、ステップ容量、初期A=0、並列分割、不変の物質入力はモデルで共通です。**
異なる物質は別MPI群に配置します。x/y/z方向・回転するAにも対応します。
Aは直交座標のA/c、dtは原子時間、返り値は原子単位の電荷電流密度jです。
handle経由の値は変換済みなので、再び符号反転しないでください。
テキスト出力列の符号はSALMONの既存定義に従います。
状態ごとのRT・電流とエネルギー出力に対応し、共通名を使う任意解析出力は従来の別状態経路を使います。
legacy初期化とhandle初期化は同一プロセスで混ぜられません。
初期化・メモリ確保・I/O・MPI異常一般について新たな復帰保証を設けるものではありません。

## 結晶TDDFTのAと観測量の時間ステップ

`a = A/c` と書くと、middlepoint法の電子更新 `n-1 → n` は
`(a[n-1] + a[n])/2` を使います。運動項と非局所擬ポテンシャルの位相は、
どちらもこの同じ中点値です。更新後の電流・エネルギーの評価では、両方を
`a[n]` に揃えます。電流だけを更新後のAへ切り替えて位相を中点のまま残しません。

FDTDとの結合では、この電子更新に対してEは場の半ステップ番号`2n`、
更新後のA・電子状態・電流は`2n+1`です。EからAを積分する処理と、
ハミルトニアン・擬ポテンシャルに同じAを設定する処理は別々に確認します。

通常XCの観測量評価をこの規約に修正しています。固定イオン・指定済みの同じA時系列なら
伝播する波動関数は変わりませんが、電流・エネルギーの値は修正されます。
その電流を場へ戻す自己無撞着計算は、その後の場と電子状態も変わり得ます。
この変更は分子のE駆動や空間依存Aを使う電子格子上のMaxwell計算の更新順を変更しません。
直接再開には、保存に使ったものと対応する計算ライブラリを使ってください。

## 通常の複数点配置

`NativeTDDFTBackend(..., shared_model=True)` と
`assemble_native_layers(..., points_per_group={"si-tddft": 2})` で明示的に有効にします。
`ranks_per_point["si-tddft"]` は共有する物質群のランク数で、分割の積と一致させます。
物質ID、点ID、並び、厚み、LD領域を維持したまま、同じモデルの電子点を群にまとめます。
既定の1点1群・`create_state` は変わりません。ResponseSessionが `open_group` を呼び、
モデルと返された状態を管理します。

```sh
mpiexec -n 4 python -m salmonpy.examples.mpi_mixed_native \
  STANDARD_BUILD SERIAL_RUNTIME INITIAL_BUNDLE NEW_OUTPUT \
  --layers mixed_shared_tddft_layers.json --tddft-ranks 2 \
  --tddft-points-per-group 2 --steps 128 --dt .003 --protect-steps
```

JSONはインストール先 `salmonpy/examples/` からコピーするか絶対パスで指定します。
場1＋SBE1＋共有TDDFT2ランクと2種類のローカルLDを使います。
共有オプションを省く独立実行は6ランクです。
`mixed_shared_tddft_hse_both_layers.json` はHSEも2点置く例です。
適切なHSE引数と `--hse-points-per-group 2` を併用すると、TDDFTとHSEそれぞれで共有できます。
異なる物質間でモデルを共用する意味ではありません。
資源予算は警告で、実行可能な計算を止めません。実際のランク数と計画の不一致はエラーです。

`--direct-save-at 63` と、新しい実行での `--direct-resume CHECKPOINT` により、
同じトポロジーの場・LD・SBE・各TDDFT状態を一括で直接保存／再開します。
失敗時に元の状態を保つ復元は全所有者の候補を準備してから公開します。準備途中の扱える失敗では元の全状態を保持します。
状態の電流メタデータも計算処理復元用の別状態を作る前に検査します。
詳しくは [結合](COUPLED.md)・[分散実行](DISTRIBUTED.md) を参照してください。

## 検証範囲

`tools/test_python_shared_tddft_mpi.py BUILD INITIAL_BUNDLE NEW_OUTPUT --size 2`
は6ランク・3群で、異なる3成分Aを与えた共有2状態を独立2実行と比較します。
直接保存からの再開、NaN/Inf/複素Aの拒否、兄弟状態・空モデルからの再作成も検査します。
`--rgrid` で軌道分割から空間分割へ切り替えます。

PZ・Libxc-PZ/PBE・TB-mBJ自動／固定について、MPI1・軌道2・空間2で局所検証します。
通常のLD/SBE/TDDFT2点混在例では、独立／共有実行と直接再開、群内の最後のランクでの
復元途中失敗・再試行を比較します。小さい既存入力による所有権・数値一致の検証であり、
物性の収束保証ではありません。新しいGSデータの収集やFortran計算ルーチン変更は行いません。
低水準の規約は [計算処理 C仕様](STANDARD_HANDLES.md) を参照してください。

## 異なる物質入力：現在の対応と残作業

**別々のMPI物質群なら、異なる入力のTDDFTを同時に使えます。** 各群の中では同じ物質入力の
複数点を共有できます。通常サンプルの `--layers` と `--tddft-materials FILE` を組み合わせ、
物質IDごとにローカルの初期状態、入力ファイル、並列分割、共有点数を指定します。

```json
{
  "schema": "salmonpy.native-tddft-materials/1",
  "materials": {
    "silicon-pbe": {
      "bundle": "./pbe-initial",
      "input_file": "rt.inp",
      "decomposition": [1, 2, 1, 1, 1],
      "points_per_group": 2
    },
    "silicon-tbmbj": {
      "bundle": "./tbmbj-initial",
      "decomposition": [1, 2, 1, 1, 1],
      "points_per_group": 2
    }
  }
}
```

相対パスはカタログの場所から解決します。絶対ローカルパスも使えます。
管理・ログインノードなどでGS・擬ポテンシャル・入力一式を準備し、計算前に転送してください。
ローダーによる通信・ダウンロード・ビルドはありません。
既定は `input_file="rt.inp"`、分割 `[1,1,1,1,1]`、共有点数1です。
点数1は従来の別状態経路、2以上は上記の共有設定を使います。
分割はk・軌道・x・y・zで、積がその物質群のランク数です。
入力が同じでも異なるIDは別モデル・別群に置きます。結合dtは全群共通で、サブサイクルは導入しません。

層配置の `material_id` がカタログ内のIDを選びます。
同梱の `mixed_distinct_tddft_layers.json` はSBE1点、PBE2点、TB-mBJ2点、真空と2種類のLDを配置します。
内部MPI2・共有点数2なら場1＋SBE1＋PBE2＋TB-mBJ2で6ランク、共有点数1なら10ランクです。
`distinct_tddft_materials.json` を入力の近くへコピーして参照を編集します。

```sh
mpiexec -n 6 python -m salmonpy.examples.mpi_mixed_native \
  STANDARD_BUILD SERIAL_RUNTIME DEFAULT_INITIAL NEW_OUTPUT \
  --layers mixed_distinct_tddft_layers.json --tddft-materials materials.json \
  --steps 128 --dt .003 --protect-steps
```

位置引数 `DEFAULT_INITIAL` は既存の `si-tddft`／HSE用の互換既定値です。
カタログの独自IDだけを使う場合は読みません。カタログの `si-tddft` は既定値を上書きします。
未使用の既定値・パスは再開条件に含めません。
入力ハッシュ、初期状態の識別情報、MPI配置、資源助言は各物質の実際の入力を参照します。
`sbe-point`、`hse-point`、`drude`、`lorentz` は予約済みです。
カタログの未使用項目は残せます。未知の項目、重複キー、不正な分割は計算状態の初期化前に拒否します。
資源の不足見積もりは警告のみです。既存の一括直接保存／再開と保護付き失敗・再試行も使えます。

**同一プロセス内の異入力モデルは、明示的な登録APIで利用できます。**
[登録・切替ガイド](TDDFT_REGISTRY.md)と `examples/tddft_models.py` を参照してください。
モデル別の入力・初期化後の設定・最適化テーブル・XC作業領域を切り替え、各状態の波動関数・
時刻・保存／復元資源を独立に保ちます。従来の `open_model`／通常配置の仕様は維持します。

通常の物質ID配置から同一群への登録は model_groups 指定で接続済みです。残る工程はGS全体の
コンテキスト化、特殊資源（SOC／+U／DCなど）の所有化です。MPI付帯・タイマー・同期的な
互換ビューはプロセス共通で、同時スレッド実行には対応しません。
既存Si入力の異なるセル・原子数・16³／8³格子・k点数、5種類のXCを使った試験は実装一致の確認です。
異元素の物性精度や収束を保証する試験ではありません。

## モデル所有の初期化入力（2026-11-18）

標準計算処理の `s_model_inputs` が227項目の初期化設定を所有するようになりました。
セル・格子・k点、擬ポテンシャル／XCの参照と係数、電子数・占有・混合条件、
伝播・dt・容量・並列設定、出力条件、入力単位、原子配置・元素ID・原子名を含みます。
割当配列は深いコピーで、元の共有入力や複製先を変更しても保存したモデル設定は変わりません。
未保存の設定は有効化できません。単位表は保存した単位選択から再構成し、
変換済みの物理入力を二重換算しません。

計算処理の `rt_model` がこの設定と初期Aを所有し、`open_initial_state(owner,...)` へ
所有者を明示的に渡します。従来の初期化計算ルーチンには同期的な互換ビューを設定します。
RT状態はモデルへの参照を借りるだけで、兄弟状態の終了時にモデルを破棄しません。
空になったモデルから元の入力で状態を再作成できます。波動関数、稼働中のMPI／Libxc資源、
RT保存ペイロードを入力レコードにコピーする変更ではありません。

モデル所有の設定レコード、明示的初期化境界、パーサー作業領域と既定値に加え、
登録・選択とPython接続も実装しました。既定APIの対応範囲・数値更新順・保存形式を維持し、
新しいレジストリABIを追加しています。詳細は上記ガイドを参照してください。

開発者用 `tools/test_model_input_ownership.py SOURCE NEW_OUTPUT --fc gfortran` は、
実際のFortranレコードをコンパイルし、2入力のコピー・原子数変更・切替・解放を検査します。
`test_standard_tddft_handles_mpi.py` で新旧ライブラリを比較し、
`test_standard_checkpoint_finite_mpi.py` で群内1ランクの保存データを故意に壊して、
復元Aの各成分のNaN／Infinity拒否と正常な再開を検証します。
IEEE判定は全対象要素へのスカラー呼び出しです。
新しい実行物はソース・オブジェクト監査を行い、変更のない検証済み実行物は記録済みSHA256を照合します。
新しいGS入力の作成・収集は不要です。GNUによる局所ビルドと富士通コンパイラでの確認は区別し、
後者を未実測のまま対応済みとは記録しません。

## モデル所有のパーサー作業領域と既定値（2026-11-18）

標準計算処理モデルごとの `s_input_parser` を `read_input(path, parser)` に渡します。
namelist読込み結果、座標ブロックの有無、scratch接続、各読込みの `defaults` と最終 `values`
を所有します。既定値の代入順・式と物理単位の換算順は維持しました。
入力ごとに単位を決めてから既定値を生成し、前の原子配列・座標モードを引き継ぎません。
workerによるdt・容量・並列分割の設定と座標読込みの後に最終値を保存します。

owned経路は名前のないFortran scratch接続を使い、分割した入力を消費するまで保持し、
完了時に接続を閉じて番号を初期化します。既存の `.namelist.tmp` や座標・reentrance一時ファイルを
上書きしません。読込み状態と座標フラグはMPI群内で一致させ、接続番号はrootだけが持ちます。
診断ログは `parser.log_path`（既定 `variables.log`）で指定でき、同じフォルダで複数の入力を
読む場合は別のログ名を指定します。入力内のファイル参照は従来どおり作業ディレクトリ基準です。
読込み時のダウンロードやビルドはありません。

従来の `read_input()`／`read_input(path)` は明示的なlegacy作業領域と名前付き一時ファイルを
維持します。後のMD速度読込みが座標一時ファイルを使うため、この経路は変えません。
所有する値のレコードは標準scalar TDDFT用の選択項目であり、FDTD／SBE／DC全入力の所有化ではありません。
パーサーと数値初期化の実行には同期的な互換ビューが残ります。これは順次読込みの独立化で、
並行スレッドや同一プロセスで異入力モデルを同時伝播する機能ではありません。
既存の異常処理方針は維持し、一般のI/O・MPI異常からの復帰は追加しません。

開発者用 `tools/test_parser_ownership.py BUILD_JSON NEW_OUTPUT --fc mpifort --mpiexec mpiexec --ranks 2`
は、ビルド記録のディレクトリにある一致したコンパイラのmoduleファイルを使い、実際のFortranパーサーを検査します。
A→B→A、作業領域の再利用、単位・原子数・直交／外部縮約／座標なしの切替、
XC・k点・パルス・混合条件の省略値、2つのscratch入力の交互消費、接続の解放を確認します。
別プロセスでの従来読込みと診断ログが完全一致し、既存の名前付き一時ファイルも保たれます。
MPI1／2で実施でき、GSデータは不要です。新旧計算処理のXC・MPI・直接再開・混在比較で数値一致も確認します。

新しい標準TDDFTのtimer protocol1では、共有状態の `state.timing_seconds` でrankローカルの完了済み区間（total、initialization、density、hartree、秒）を読めます。各ハンドルがタイマーを保持し、他状態・呼び出し元プログラムで実行した時間や待機中の区間を混ぜません。totalは継続中の区間を含まないため実行中は0の場合があります。照会は物質MPI群で全ランクから呼びます。計測は保存データに含めず、復元で使用済み計算時間を巻き戻しません。旧計算プログラムは通常の計算を続けられますが、新しい照会には明示的に対応版をビルドしてください。この対応は標準TDDFTハンドルに限り、HSE・従来singleton・スレッド同時実行の分離は別です。

## 共有・登録TDDFTの状態ごとのモード

`NativeTDDFTBackend(..., shared_model=True, execution_mode="performance")`
または `registry_model=True` で、通常のセッションが作る状態の既定値を指定します。
モデルを直接使う場合は `model.new_state(point_id, execution_mode="checked")`
または `"performance"` で状態ごとに上書きできます。省略時はモデルの既定値を
使います。`registry.open_model(..., execution_mode=...)` で登録モデルごとの
既定値も選べます。作成後の状態の選択は読み取り専用で、他の状態とは独立です。
同じ登録管理器を再利用しても、前の物質設定のモードを引き継ぎません。

性能更新でもハンドルの世代・有効期間・容量・ABIの境界はローカルに検査します。
トークン・新旧A・モデル切替の診断合意、数値走査、自動退避を省きます。
モデル入力・作業領域の切替と物理計算に必要な通信は残します。通常モードの
状態は従来の集合的検査を維持します。明示的な保存／復元は検査し、復元先の
状態のモードを変えません。性能更新の失敗時に自動復元・再試行は保証しません。

合成入力で通常・性能状態の交互更新、独立実行との比較、4種類のXC、異なる
PZ↔TB-mBJ・Libxc-PZ↔PBEの登録切替を内部1・2ランクで確認しています。
実材料の収束検証や速度評価ではありません。


SOC非共線の追加範囲は[Niの接続検証](NICKEL_SOC.md)を参照してください。PZ/Libxc-PZ/PBEの入口を追加し、Ni Libxc-PBE・内部MPI 1/2で状態独立性と直接復元を検証済みです。TB-mBJ・HSEのSOCは対象外です。


SOCの深部数値異常からの自動復帰は `checked`、検査・保護用コピーを省く更新は `performance` を使います。Ni PBE・k点MPI 1/2で状態・出力の保持と再試行を確認しました。詳しくは[NICKEL_SOC.md](NICKEL_SOC.md)を参照してください。

SOCはCPUでk点・軌道・空間並列を利用できます。空間並列は直交セルと対応する計算ライブラリが必要です。
`checked`は対応する数値異常から状態と出力を保持して復帰し、`performance`は明示的な保護から復元できます。
対応条件と実行例は[NICKEL_SOC.md](NICKEL_SOC.md)を参照してください。
