# Pythonから電子計算と光伝播を結合する（MPI・実験的機能）

[English](COUPLED.en.md)

外から電場を与えて電流を計算するだけでなく、電子が生む電流をFDTDへ戻し、光と物質の相互作用を計算する方法です。Pythonから両方の計算を一ステップずつ進めます。

一つのMPIジョブを、電磁場を担当するプロセス群と、物質の電子状態を担当するプロセス群に分けます。各物質のk点・軌道・実空間の並列計算は、その物質を担当する群の中で行います。LDの状態はFDTDを担当する群が管理します。計算中に別の `mpiexec` を起動する必要はありません。

マクロ点は、電磁場の格子上で物質応答を計算する点です。まず一つの物質群に一物質・一マクロ点を割り当てます。同じ物質を複数点で使う場合はモデル共有、異なる物質を同じ群で扱う場合はモデル登録の説明へ進んでください。以下に各方法の条件を示します。

電磁場は `salmonpy.coupled.NativeEHField`、電子計算は `NativeTDDFTMaterialProvider` と `NativeTDDFTBackend` で用意し、`CoupledStepper` で結びます。これらはAPIの名前です。独立した計算を別プロセスで実行する場合は `TDDFTResponseBackend` または通常のFDTD実行方法を使います。

## 一つの計算状態か、複数の計算状態か

電子計算の入口は、必要な状態の数と物質入力で選びます。以下の名前はPythonメソッド名です。

| 目的 | 入口 | 状態の扱い |
|---|---|---|
| 一つの物質・一つの点から始める | `backend.create_state(...)` | この方法では各プロセスで初期化は1回まで |
| 同じ物質を複数の点や波形で計算する | `backend.open_model(...)` → `model.new_state(...)` | 共通の物質入力から独立した計算状態を作る |
| 異なる物質入力を同じMPI群で扱う | `backend.open_registry(...)` → `registry.open_model(...)` | モデルごとに入力を保持し、同じ群で順に呼び出す |

複数状態はメインスレッドから順に操作します。スレッドからの同時実行を意味しません。実際に使える汎関数・対称性・MPI分割は、各専用ガイドと使う計算ライブラリの対応範囲を確認してください。FDTDを担当する各プロセスでは、正常に初期化する場は一つです。初期化エラー後の再試行は、ライブラリが復帰に対応するエラーに限って可能です。

## 次元と応答モデルの選び方

3次元の場・マクロ点配置を扱えますが、TDDFTは各マクロ点に電子状態を持つため、
実用計算では**まず1次元の伝播・層構造を推奨**します。ここでの次元は電磁場・マクロ配置の次元で、
微視的なDFT/TDDFTの電子状態を1次元化する意味ではありません。

**電子応答を結合する3次元計算は、SBEまたはユーザー作成の電流計算コードを使う場合に推奨**します。
TDDFTの3次元計算は禁止しませんが、必要な物理・独立状態数・メモリ・計算時間を確認して選びます。
SBEや独自コードも、モデルの有効範囲と各マクロ点の独立状態、A/c→電荷電流密度の仕様を満たす必要があります。
通常の混在サンプルはSBEとFDTDのE/H更新の結合に対応します。自動的に1次元化する機能ではありません。
LD単独の3次元FDTDは別の利用経路です。

現在の40³格子・TDDFT二点のサンプルは接続回帰用です。一般利用向けの3次元TDDFT推奨例でも、
横方向に一様な1次元多層膜の実装例でもありません。格子の横方向を単に1セルへ減らすだけでは1次元化できません。

## 初回準備と資源

最初に、目的・使える総メモリ・総CPU並列数を確認します。標準例は場2ランク＋物質2群×2ランク＝6ランク、
電子状態は2個です。各ランク1スレッドで始め、OpenMPとBLASの追加スレッドを予算へ含めます。
混在サンプルには不確実性付きのメモリ見積もり・計測があります。予算超過は警告のみで上限を強制しません。小さなGSで測定してから規模を増やします。

この入口には**実行環境のMPIで明示的に構築した共有ライブラリ**が必要です。
配布用直列計算プログラムや通信検査用ブリッジは代用できません。import時にはビルドしません。
現在のビルド手順はmacOS/Linux・GNU互換コンパイラを対象とします。

```sh
python tools/prepare_salmon_runtime.py NEW_SOURCE
python tools/build_embedded_tddft.py NEW_SOURCE NEW_BUILD --jobs 2 \
  --cmake-arg=-DCMAKE_Fortran_COMPILER=mpifort \
  --cmake-arg=-DCMAKE_C_COMPILER=mpicc \
  --cmake-arg=-DBLA_VENDOR=OpenBLAS \
  --cmake-arg=-DOPENMP_FLAGS=-fopenmp \
  --cmake-arg=-DCMAKE_BUILD_TYPE=Release \
  --cmake-arg='-DCMAKE_Fortran_FLAGS_RELEASE=-O2 -ffree-line-length-none -fallow-argument-mismatch'
```

MPIラッパー・BLASの所在は環境に合わせます。Cラッパーも指定したOpenMPオプションに対応する必要があります。
ビルドはMPI・PICを有効にし、ソースとオブジェクトの固有値ドライバー監査を行い、
ライブラリSHA256・ソースハッシュ・構築コマンドを `NEW_BUILD/build.json` に記録します。
wheelにも構築ツールを `salmonpy/_runtime_source/tools` に同梱します。
`importlib.resources.files('salmonpy').joinpath('_runtime_source')` で場所を調べられます。

mpi4pyとライブラリは同じMPIを使用します。共有ライブラリは呼び出し元プログラム依存で、他のMPI環境へコピーして動くとは限りません。
Libxcが必要なら対応したビルド設定を明示します。今回の内部分割の数値検証はPZとTB-mBJです。

## 実行例

```sh
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 mpiexec -n 6 python -m salmonpy.examples.mpi_coupled_tddft \
  NEW_BUILD/build.json GS_BUNDLE RT_INPUT NEW_OUTPUT
```

`GS_BUNDLE` は保存済みGS、相対パスの擬ポテンシャル、RT入力を含む自己完結した束です。
`RT_INPUT` はその中のファイル名。GS作成条件と汎関数・格子などを一致させます。
このローダーはDFTを自動実行せず、保存形式も変換しません。
`NEW_OUTPUT` は同じ計算群の全ランクから読める共有ファイルシステム上の新規保存先です。

標準例は40³の場格子と二つの隣接する電子マクロセルです。人工的な光パルスによる接続確認で、
収束した多層膜や実験を再現する条件ではありません。`--field-ranks 1 --material-ranks 2` なら計5ランクです。
各物質群の内部分割は `(k, orbital, x, y, z)`、積は群のランク数と一致させます。
標準例は軌道方向を分割します。k点・バンド数・実空間格子に対して有効な分割を選びます。

`ResponseSession` に渡す `MaterialBinding` のprovider/backendは利用者のコードへ交換できます。
初期物質の読み込みとA→Jの物理計算は別の仕様です。物理的な**電荷電流密度**を返し、
電子数電流の符号変換を二重に行わないでください。群内通信は渡された `solver_comm` に限定します。

## 1ランクのMultiscale1Dと分散TDDFT

`CoupledStepper.from_multiscale(context, bindings, field=None)` はPythonの
`Multiscale1D` 状態を同じ物質群へ接続します。場群は1ランクに限定し、そのランクで
`model.new_state(dt=dt, steps=steps)` を作り、物質ランクでは `None` を渡します。
全ランクでfactoryと `step()` を呼びます。物質セル1〜Nを
`context.plan.point_ids` の順に対応付けます。同じGSを二つの物質群に渡しても、
時間発展中の状態は独立です。場1ランク＋物質2群×2ランクなら計5ランクです。

```sh
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 mpiexec -n 5 python -m salmonpy.examples.mpi_multiscale_tddft \
  NEW_BUILD/build.json GS_BUNDLE RT_INPUT NEW_OUTPUT --material-ranks 2 --steps 400
```

`--material-ranks 1` なら計3ランクで起動します。物質2セル、間隔5原子単位、
真空(300, 50)、dt=0.02原子単位、z偏光の人工パルスを使います。軌道分割は用意したGSに
適合させてください。`response.json` に端点A/j履歴と時刻宣言、`field.npz` にt=0を含む
格子全体のA履歴、`communication.json` に計測を保存します。再開ファイルではありません。
サンプルはビルドやGS準備を自動実行しません。

factoryは計算処理状態を作る前に物質点のA(0)を検査します。非ゼロなら点と値を示して拒否します。
左側の真空セルを増やすか、入射パルスを遅らせてください。真空中の入射Aは非ゼロでも構いません。
物質点のA(0)を黙ってゼロへ置き換えません。初版は物質点の初期Aがゼロの場合に限定し、
計算処理状態は一プロセス一回の生成という制約を保持します。

更新順は「前回j → Multiscale1Dの場更新 → 新しいA → 物質更新」です。
初回フィードバックはゼロです。場と物質の時計はともにn·dt（offset 0）で、
E/H用の半ステップ変換は適用しません。`step()` は場ランクで点順の
`A_over_c` と `J_charge` を返します。元の場状態を保持すれば `grid_A` と `grid_E`
を読めます。後者は中心差分で時刻(n−1)·dtです。
返される各frameの `E_time` にEの時刻を明記します。Multiscale1Dの中心差分Eは
(n−1)·dt、Aはn·dtで、計算処理E/HのEはn·dtです。配列の添字だけでEとAを同時刻と扱わないでください。
`coupled.response.initial_current` は点IDをキーとする物理的なt=0電流の辞書です。
独自状態が初期電流を公開しない場合は `None` です。この観測量と初回のゼロフィードバックは区別します。
サンプルは `response.json` の `initial_current` に保存します。

終了は `coupled.response`、存在するランクの `coupled.field`、Pythonコンテキストの順です。
時間発展後の失敗では結合を無効にし、群をまたいだ原子的な巻き戻しや再開は保証しません。

`coupled.response.communication_report()` は全ランクで呼び、ランク別の通信計測を取得します。
A配布とj回収を物質計算とは別に測ります。通信呼び出し時間には他ランクの待ち時間も入り得るため、
純粋なネットワーク遅延とは解釈しません。計測の失敗と計算の失敗を分け、取得不能な値はその旨を残します。
単一呼び出し元プログラムの計測から複数ノードでの拡張性能を主張しません。

受け入れ検査はSALMONの二点Weylマルチスケール出力に対する格子全体のAと各点のjの比較、
直列ワーカーとの比較、ランク数を変えた一致確認です。合成GSによる検査は接続と更新順の検証で、
物理的な収束検証とは区別します。

## 電磁場を渡す時刻と格子上の位置

新しい方式名は `salmonpy.eh-centered-current/1`。従来のWeyl形式のマルチスケールとは
離散化が異なるため、両者のビット一致は主張しません。通常のFDTD更新順と光源の評価時刻は維持します。

| 量 | 場の時計での時刻 |
|---|---|
| n回目更新後のE、従来ログのE/H（Hは時間平均） | n·dt |
| 新しいAとJ、更新後の生のH | (n+1/2)·dt |
| E更新へ渡す前回のJ | (n−1/2)·dt |

電子計算のローカル時刻0は、場の時刻dt/2です。初期E・H・AとフィードバックJは0に固定します。
初期GSの計算電流が非ゼロでも、勝手に初期フィードバックへ代入しません。
更新は「前回JでE/H更新 → EからA更新 → TDDFTでJ更新」の順です。
`A_new = A_old − dt * S(E_n)` で、結晶に渡す量は常にA/cです。

この表は `salmonpy.time/1` の形で宣言しています（`NativeEHField.timing`：入力 j は offset ½・lag 1・t=0 不使用、出力 A は offset ½）。
`CoupledStepper` は全点の物質側の宣言を MPI で集め、電子系の時計（場の時計 + ½、`ELECTRONIC_CLOCK_OFFSET`）に置いて照合し、
食い違いがあれば最初のステップの前に拒否します。照合結果は `stepper.timing` と `response.json` に残ります。[FIELDS.md](FIELDS.md) を参照してください。

Sは既存FDTDの観測位置への補間と同じです。例えばExは `(i,j,k)` と `(i−1,j,k)` の辺の平均、
Ey/Ezはそれぞれy/z方向の隣接辺の平均です。電流はその転置写像で、対応する二辺へ半分ずつ戻します。
各マクロ点が一様格子の一セル体積を代表するため、追加の体積係数はありません。
MPI境界では各場ランクが自分の所有する辺へ加算します。

マクロ点は境界から10セル以上離し、光源面・その周囲と、背景のLD/誘電体の構成則が使われる辺を避けます。
周囲3³セルが真空であることを検査します。LDを別の場所に置くことはできます。

## 保存する電磁場・出力・制限

- 一プロセスにつき計算処理状態の生成は一回です。同じプロセスで再初期化・複数状態・スレッド共有はできません。
  同じGSから独立した二群の計算は可能です。別の試行は新しいMPIジョブで始めます。
- 入力・初期状態・dt・内部分割は生成時に固定。各段でAまたは前回Jだけを渡します。
- SALMONの相対I/Oに合わせ、呼び出し中だけ作業ディレクトリを切り替え、戻します。
  メインスレッド限定です。同じプロセスで並行する相対パスI/Oを行わないでください。
- 反復の途中で場または物質を単独に進めると、結合器は同期不一致を拒否します。
  計算処理更新後の異常では再試行・巻き戻しをしません。close後、新しいジョブで再開します。
- closeは物質応答 → 場 → Pythonコンテキストの順に全群で実行します。FortranはMPI自体を終了しません。
  計算処理の停止・通信障害にはジョブ側のタイムアウトが必要で、サンプルは異常時にジョブ全体を停止します。
- 再開、非ゼロ初期場、インパルス光源、回転、異なるマクロ体積、時間サブサイクル、TTMはこの入口では未対応です。

`response.json` は点ID順のA/c、E、前回J、新しい電荷電流と二つの時計を保持します。
場の `salmonpy-coupled-field.json` は写像、MPI分割、ライブラリ、終了状態を記録します。
物質ごとの作業コピーとSALMON出力も残します。大きい密度などはRT入力で選択し、保存間隔を指定します。
これらのJSONは完全な再開ファイルではありません。

ローカル回帰では既存の真空/LD FDTDとの一致、三方向のMPI境界の電流注入、
場1/2ランクの一致、TDDFTのA履歴再実行を確認しています。物理量の格子・時間・GS収束と大規模性能は別途確認が必要です。

## 異なる材料と時間刻み

同じFDTDへ接続するすべての物質状態は、材料・格子・XCが異なってもFDTDと共通のdtを使います。異なるdtの独立状態を作れることと、異なるdtで場と結合できることは別です。現在の結合器は各点の時刻宣言を開始前に照合し、dt不一致を拒否します。整数比（例：物質dtが場dtの半分）も、そのまま接続できません。

Yee結合の半ステップずれと前回電流のlag1は維持します。同じdtでも半ステップの対応が違えば拒否します。サブサイクル、途中のAの補間、返す電流の時間平均は未実装で、自動適用しません。複数のdtが必要な場合は、独立した計算として扱うか、別途検証した時間結合アダプターが必要です。

## LD・SBE・TDDFTの混在に向けた入口

`mpi_mixed_multiscale`は、同じ1次元場にLDと合成SBEを配置する接続サンプルです。
```sh
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 mpiexec -n 3 python -m salmonpy.examples.mpi_mixed_multiscale NEW_OUTPUT
```
場1ランク、物質点2ランクで動かし、非ゼロの応答と独立した直列更新との一致を検査します。点ID10/20と物質キー、A/c・電荷電流j、通信時間を保存します。LDは端点A差分からEを得ます。FDTDのE/H更新の半陰的LD更新と同じ方式ではありません。

4ランクにして`--runtime RUNTIME --bundle GS_BUNDLE --input rt.inp`を指定すると、管理済み直列TDDFTワーカーを第三点に接続する入口を使えます。Si入門系の実GS（PZ、16³格子、2×2×2 k点）を用いた4ランク・100ステップの三種類混在実行は、直列計算と完全一致しました。実GSと対応計算プログラムを明示的に用意してください。これは管理済み直列ワーカーの検証で、TDDFT群内部のMPI並列とは別の経路です。光学物性の収束は保証しません。記録: `docs/mixed-three-material-validation-2026-11-16.md`。

最終構成は、FDTDランク内の多数のLD状態と、別MPI群のSBE/TDDFT状態の混在です。この小規模サンプルの「LD一セルに一ランク」を本番の配置方針にしないでください。実材料の収束や三次元混在対応を保証するサンプルではありません。

## FDTDのE/H更新内のLDと、SBE・内部MPI TDDFT

`mpi_mixed_native`は、場1ランクが二種類のLD領域を持ち、別の1ランクがSBE、別の2ランクが1点のTDDFTを担当する接続試験です。外側4ランクでTDDFTの軌道分割を内部2ランクにします。
```sh
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 mpiexec -n 4 python -m salmonpy.examples.mpi_mixed_native BUILD_JSON SERIAL_RUNTIME GS_BUNDLE NEW_OUTPUT
```
`--tddft-ranks 1`なら外側3ランクです。`--without-ld`はLD領域を真空にする対照条件です。BUILD_JSONは同じMPI環境で明示ビルドした`tools/build_embedded_tddft.py`の記録、SERIAL_RUNTIMEは応答再計算の比較用です。自動ビルド・ダウンロードは行いません。

LDはFDTDのE/H更新の既存の係数・補助量・更新順を使います。電子状態はA/c駆動を維持し、受け渡しは電荷電流jです。点ID10はSBE、20はTDDFT、LD領域ID1/2は場の材料格子上で管理します。電子点の周辺はLDと重複させません。半ステップずれの場時計と物質の局所時計を区別します。

この40³格子・電子2点の小さな三次元配置は接続検査用です。実用TDDFTは引き続き一次元伝播を推奨します。巨大な多数LD、分散した複数FDTDランク、全計算再開、物理収束の検証とは区別してください。計算処理異常は回復可能ではなく、サンプルはMPIジョブを停止します。

検証済み: 128ステップ、TDDFT内部1/2ランクの場・電流比較、直列応答再計算、LDなし対照、LD単独の従来一致、wheel導入後実行。範囲と誤差は`docs/native-mixed-material-validation-2026-11-16.md`を参照してください。

### FDTD群も並列化する

場をy方向に2分割する例（場2＋SBE1＋TDDFT1＝外側4ランク）:
```sh
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 mpiexec -n 4 python -m salmonpy.examples.mpi_mixed_native BUILD_JSON SERIAL_RUNTIME GS_BUNDLE NEW_OUTPUT --field-grid 1 2 1 --tddft-ranks 1 --compare REFERENCE_OUTPUT
```
REFERENCE_OUTPUTには、同じサンプルを場1ランク・TDDFT1ランク（外側3ランク）で実行した出力を指定します。`--compare`を省略すれば単独実行です。比較は同じステップ数・dt・材料設定・点順を要求し、A/c・E・jの履歴を確認します。必要な外側ランク数は`product(field-grid)+1+tddft-ranks`です。

x/y/z各方向の2分割は、128ステップで場1ランクの結果と完全一致しました。y/z分割では両LD材料が両方の場区画に分かれます。場2ランクとTDDFT内部2ランクを同時に使う5ランク構成は、今回の4コア枠では未検証です。大規模性能・メモリ上限の保証ではありません。記録: `docs/distributed-field-mixed-validation-2026-11-16.md`。

## 物質ID・並び・厚みからMPI構成を準備する

`salmonpy.layers.assemble_native_layers` は `salmonpy.native-layers/1` の配置と、物質IDからLDモデルまたは `MaterialBinding` への辞書を受け取ります。物理パラメータと初期状態は既存の設定ローダーで用意し、配置ではIDを参照します。自作応答コードも明示的な `MaterialBinding` で接続できます。

```python
import json
from salmonpy.layers import assemble_native_layers

layout = json.loads(layout_path.read_text())
assembly = assemble_native_layers(
    layout, materials, grid=grid, dt=dt, steps=steps, source=source,
    field_grid=(1, 1, 1),
    ranks_per_point={"sbe-point": 1, "si-tddft": 2}, rank_budget=4,
)
report = assembly.record()
print(report["required_ranks"], report["layers"])
# parallel_plan を ParallelContext.create、calculation と points を
# NativeEHField、bindings を ResponseSession に渡します。
```

上の変数は事前に用意したモデル、Grid、PlaneWaveと計算条件です。構成の作成はソルバー・MPIの起動やダウンロードをしません。表示された必要ランク数で、環境のMPI起動方法を使います。

`examples/mixed_layers.json` はSBE、Si、真空、Drude、Lorentzの順の例です。長さは明示的にBohr。各層は一意な `id`、`material_id`（真空はnull）、`thickness`、横方向2軸の `transverse_cells` を持ちます。`axis` は光源の伝播軸と一致させ、`origin_cell` は最初の軸方向セルと横方向の基準セルです。厚みは格子幅で切り上げ、要求値・実際の厚み・終端を含まないセル範囲・物質ID・ランクを記録します。横方向の開始位置は `anchor-count//2` です。

電子物質の各格子セルに独立した状態とMPI群を割り当て、LDは場のランク内で管理します。有限の直方体配置であり、無限膜の均質化や代表点への間引きはしません。厚みや断面積を増やすと電子点と必要ランクが増えます。ランク予算超過は警告のみで、全物質点と必要ランク数を維持します。実行には表示された必要ランク数が必要です。未知のID、計算処理不整合、吸収境界との重なり、LD構成則の近傍に入る電子点は拒否します。真空の隙間も明示指定が必要です。ランク予算はメモリ上限ではなく、`memory_bytes` は未推定です。初期状態準備、MPI起動、物理的な収束確認は別途行います。

上記4ランクの `mpi_mixed_native` コマンドに `--layers 配置JSONのパス --rank-budget 4` を追加できます。このサンプルの既知IDは `sbe-point`、`si-tddft`、`drude`、`lorentz` です。公開の構成関数では任意の明示的な物質IDを使えます。SBE/LDだけの配置ではTDDFTの計算プログラムとGSは不要で、サンプルの位置引数には未使用の仮パスを指定できます。LDだけならFDTD単独入口を使います。

### 同じ物質から複数の独立点を作る

同梱の配置JSONを読み、Si層の厚みを2から4 Bohrへ変えると、Siが2セルになり、同じ初期状態を使う独立したTDDFT点が2つ作られます。

```python
import json
from pathlib import Path

layout = json.loads(Path("mixed_layers.json").read_text())
for layer in layout["layers"]:
    if layer["material_id"] == "si-tddft":
        layer["thickness"] = 4
Path("two_si_points.json").write_text(json.dumps(layout, indent=2))
```

`mpi_mixed_native` に `--layers two_si_points.json --tddft-ranks 1 --rank-budget 4` を指定して4ランクで実行します（場1＋SBE1＋TDDFT1×2）。物質IDは共通でも、点IDとMPI群と時間発展状態は別です。厚みを増やすと後続の層も移動するため、報告されるセル範囲を確認してください。

SBEを2点にする場合は、上の条件を `sbe-point` に変更します。どちらも128ステップで各点の異なるA/c履歴を独立に再生し、電流一致を確認しています。同一プロセスに複数のPythonから直接呼ぶTDDFT状態を置く検証ではありません。

### 結合サンプルの再実行による保存／再開

`mpi_mixed_native` の `--save-at 64` は64ステップで停止し、出力先の `checkpoint/` に入力照合情報とA・E・電流履歴を保存します。同じ全ステップ数・配置・ライブラリ・GS・MPI構成を指定し、新しい出力先と `--resume 保存先/checkpoint` で再開します。`--compare 連続実行の出力先` で最終履歴を比較できます。

これは初期状態から保存時刻まで場・LD・電子状態を同じ順序で再計算する再開です。過去のA・E・電流が完全一致することを検査してから続きを計算します。内部状態の直接保存ではなく、過去部分の計算時間が再び必要です。初期状態とライブラリを保持してください。現時点では同じ環境・構成の同梱サンプル専用です。汎用の結合状態アーカイブは未実装です。同梱サンプルの直接復元は次節を参照してください。

### 内部状態を直接保存して再開する

同梱の `mpi_mixed_native` で `--direct-save-at 64` を指定すると、64ステップで停止し、`OUTPUT/direct-checkpoint/` に各ランクの内部状態を保存します。同じ入力・ライブラリ・GS・MPI構成で、新しい出力先と `--direct-resume 保存先/direct-checkpoint` を指定すると、保存時刻までの時間発展を繰り返さずに再開します。全ステップ数は元の128のまま指定します。`--compare 連続実行の出力先` で比較できます。`result.json` の `restored_step` と `native_steps_this_job` が開始時刻と今回の実行ステップ数です。

保存対象は計算処理のE/H・PML、LDのP/J/Qと旧場、電子の波動関数バッファ・密度・局所ポテンシャル・Hartree履歴・RT履歴・A・電流、Pythonの積算A・直前電流・時計です。SBEの密度行列も直接保存します。復元時は静的な入力・係数・初期資源を準備してから動的状態を読みます。全ランクのファイル一覧とSHA256を記した完了ファイルがない保存、不一致の入力・ライブラリ・構成は拒否します。

対象は同じ環境・分割を使う周期結晶・中点伝播サンプルです。XCはPZ、TB-mBJ（自動／固定cval）、Libxc-PZ／PBEに対応します。Libxcには対応ライブラリを明示ビルドした計算処理計算プログラムが必要です。自作の計算コードの汎用保存、別MPI分割、HSEや他のXCは別途対応・検証が必要です。既定の失敗時に元の状態を保つ復元では扱える復元用の別状態の準備失敗時も元の状態を維持します。明示的な無保護経路や未処理の計算処理異常には再試行保証がありません。大きな状態の保存量とメモリには余裕を持たせてください。

直接保存形式v2はXC名・導関数設定・入力cvalを照合し、Libxcのハンドルは新しい初期化で再作成します。元の計算プログラムと保存ファイルのハッシュを保持してください。サンプルのRUNTIME引数には管理済み計算プログラムのほか、明示構築・監査したシリアル参照計算用のシリアル版SALMON実行ファイルも指定できます（MPI版を参照用子プロセスに使わないでください）。別のXCを試す場合は、そのXCで用意したGSとRT入力を使います。

#### TB-mBJ／Libxc-PBEの内部MPI直接再開

同じXCで準備したGS/RTバンドルを使い、外側4ランク（場1、SBE1、TDDFT軌道分割2）で実行します。`--tddft-ranks 2 --rank-budget 4 --layers 配置JSON` を指定し、連続実行、`--direct-save-at 63` で止める保存実行、新しい出力先への `--direct-resume 保存先/direct-checkpoint --compare 連続実行出力先` の順で実行してください。全ステップ数は128のままです。

TB-mBJ（自動係数／cval=1.2）とLibxc-PBEで、この構成の再開後65ステップと連続128ステップのA/c・E・電流がビット単位で一致しました。同じ二段階MPI構成での直接再開の検証であり、MPI分割を変更する再開は対象外です。場2ランクとTDDFT2ランクを同時に使うにはSBEを含め5ランクとなり、今回の4コア枠では未検証です。

直接再開のチェックサム検証はランク間で分担します。全ランクが同じ完了manifestを読み、検証がすべて成功したことを確認してから内部状態を復元します。保存先は全ランクから同じ内容を参照できる共有ディレクトリが必要です。ノードごとの異なるローカルコピーは対象外です。`result.json` の `checkpoint_validation` に各ランクの検証ファイル数・バイト数を記録します。

## 高速PR版HSEを外側MPI／FDTDへ接続する

`FastHSEMaterialProvider` と `FastHSEResponseBackend` は、高速PR版HSEの専用serialワーカーを既存のA/c→電荷電流j仕様へ接続します。FDTDは既存のMPI入口、LDは場ランク内、各HSE点は1ランクの物質群が独立した子プロセスを所有します。HSE内部MPIは使用しません。呼び出し元プログラムのカレントディレクトリを変更せず、import時にMPI初期化・ビルド・取得はしません。

```python
from salmonpy.fast_hse import FastHSEMaterialProvider, FastHSEResponseBackend
from salmonpy.material_response import MaterialBinding

binding = MaterialBinding(
    "hse-point",
    FastHSEMaterialProvider(bundle_directory, "rt.inp", max_steps=256),
    FastHSEResponseBackend(worker_build_json, existing_work_root, threads=1),
)
# このbindingを既存のassemble_native_layers / ResponseSessionへ渡します。
```

監査済み高速PR版ビルド記録から、ワーカーを新しい外部ディレクトリへ明示構築します。通常版HSEを指定しません。

```sh
python tools/build_fast_hse_worker.py FAST_PR_BUILD_JSON NEW_WORKER_DIRECTORY
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 mpiexec -n 3 python -m salmonpy.examples.mpi_mixed_native FIELD_BUILD_JSON UNUSED_REFERENCE HSE_BUNDLE NEW_OUTPUT --fast-hse-build NEW_WORKER_DIRECTORY/build.json --layers PATH_TO_mixed_hse_layers.json --dt .001 --steps 256 --rank-budget 3
```

`mixed_hse_layers.json` はLD2材料＋SBE＋HSEの配置です。`UNUSED_REFERENCE` はこのHSE専用例では未使用の位置引数で、存在しない仮パスで構いません。HSEの独立参照計算は同じ専用ワーカーで行います。場2ランクでは `mpiexec -n 4 ... --field-grid 1 2 1 --rank-budget 4` とします。各HSE群は1ランク限定です。子ワーカーがその群の割り当てCPUを使い、呼出元ランクは応答を待ちます。OpenMPを増やす場合は別途CPU予算を割り当ててください。

入力は `tddft_response`、`xc='hse06'`、明示的な高速伝播器（`hse_taylor4`／`hse_taylor4_full`／`hse_ptcn`）を含む元GS/RTバンドルです。ワーカーは選択したdtと上限ステップ数だけを設定し、他の物理条件を保持します。内部並列数は1、学習型には対応するdense-k／固定占有／全支持領域の条件が必要です。初期ゼロ場のサンプルは初期HSE電流が1e-12 au以下であることを要求し、基準電流を差し引きません。合成テスト入力は `tools/prepare_fast_hse_coupled_fixture.py` で作れますが、実材料のGSや物理収束の代わりにはなりません。

`--direct-save-at 127` で場/PML/LD/SBEとHSEワーカーの内部状態を同時刻に保存し、新しいジョブで `--direct-resume SAVE_OUTPUT/direct-checkpoint --compare CONTINUOUS_OUTPUT` を指定します。HSEのLOAD応答により受理済みステップ・電流も復元し、保存したA・結合履歴と照合します。過去127ステップを再実行せず、残り129ステップを進めます。共有保存先・同一ワーカー／初期バンドル／入力／MPI構成が必要です。新しいワーカーの初期資源作成と、検証用の独立参照再生は別途行います。

対象はmacOS/Linux向けPOSIXワーカー（`/dev/stdin`使用）です。今回の実測はApple Silicon。このワーカー方式ではHSE内部MPIを使いません。変更した分割への再開、GPU、任意計算処理の一般保存、計算処理異常後の継続は未対応です。

HSEワーカーへの入力は原子単位（unit_system=au）に限定します。内部パルスを無効にし、ae_shape1はnoneまたは明示的なゼロimpulse、ae_shape2はnone、trans_longiはtrとします。FDTDからのAと内部パルスの二重駆動を拒否します。状態のtimeは受理済みstep×dtです。

## 高速PR版HSEの内部k点MPI

`salmonpy.fast_hse_mpi.NativeFastHSEBackend` は、Python側で用意した物質コミュニケータ内で高速PR版HSEを集合的に実行します。MPIの初期化・終了は呼び出し元プログラムが管理します。import時にMPI読込やビルドは行いません。1群1点、1プロセスにつき初期化1回、メインスレッド専用です。呼出中は作業ディレクトリを一時変更するため、相対パスを使う別スレッドと併用しないでください。

`tools/prepare_hse_rt_state.py NEW_SOURCE --explicit-routing` で新しいソースを準備し、`tools/build_fast_hse_mpi.py PREPARED_SOURCE NEW_OUTPUT --jobs 2 --cmake-arg=...` で明示ビルドします。呼び出し元プログラムと同じMPIのFortran/Cコンパイラ、OpenBLAS/LAPACK、FFTW、必要ならLibxcのパスをRUNTIMEガイドに従って指定します。MPI/HSEを必須とし、GPU・Poisson-FFTW・ScaLAPACK・EigenExa構成は拒否します。記録にはソースとアダプターのハッシュを含めます。実行エンジンは固定した高速PR版のみです。

```python
from salmonpy.fast_hse import FastHSEMaterialProvider
from salmonpy.fast_hse_mpi import NativeFastHSEBackend
from salmonpy.material_response import MaterialBinding

binding = MaterialBinding("hse-point",
    FastHSEMaterialProvider(bundle_directory, "rt.inp", max_steps=256),
    NativeFastHSEBackend(mpi_build_json, existing_shared_work_root))
# assemble_native_layers / ParallelPlanでこの点に2ランクを割り当てる。
```

k点のみの1／2ランク分割に対応し、軌道と実空間は分割しません（`nproc_ob=1,nproc_rgrid=1,1,1`）。計算処理は`nproc_k`を群サイズに、dtと容量を指定値に設定します。群に十分なk点を用意してください。外場・固定占有・全支持領域の制約は上記と共通です。サンプルでは結合後の独立比較用にserialワーカーのビルド記録も指定します。

```sh
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 mpiexec -n 4 python -m salmonpy.examples.mpi_mixed_native FIELD_BUILD_JSON UNUSED_REFERENCE HSE_BUNDLE NEW_OUTPUT --fast-hse-build SERIAL_WORKER_BUILD_JSON --fast-hse-mpi-build MPI_BUILD_JSON --hse-ranks 2 --layers PATH_TO_mixed_hse_layers.json --dt .001 --steps 256 --rank-budget 4
```

場1＋SBE1＋HSE2で4ランクを使い、2種類のLDは場ランク内に保持します。同じ引数で連続実行、`--direct-save-at 127`、新しいジョブで`--direct-resume SAVE_OUTPUT/direct-checkpoint --compare CONTINUOUS_OUTPUT`を順に実行します。HSEは群サイズ・群内ランク・k範囲を含むランク別ファイルを保存し、全ファイルを検査してから数値状態を反映します。初期化は静的な交換／FFT資源を再構築し、過去の時間発展は行いません。同じバイナリ・元GS・入力・分割と共有保存先が必要です。早期の不正・切断ファイルは数値反映前に拒否します。既定の失敗時に元の状態を保つ復元では、扱える復元用の別状態の準備失敗時も元の全状態を維持します。明示した無保護経路や未処理の計算処理異常には再試行保証がありません。

Apple Siliconで微視的8³格子・4×1×1 k点の合成入力を実測しました。Taylor／学習PT-CNとも場1＋SBE1＋HSE2、dt=.001、256ステップ中127で直接保存し、残り129回の呼出後にA/c・E・jの全履歴がビット単位で一致しました。独立serial高速PR応答との最大HSE電流差は4.07e-16／1.71e-16 auです。接続・再開の回帰検査であり、物理収束・大規模性能の保証ではありません。記録：`docs/fast-hse-kmpi-validation-2026-11-16.md`。

層構成時、計算処理は任意で `supported_group_sizes=(1,2)` のように対応ランク数を宣言できます。空でない正の整数の重複なしtupleに限定し、未対応ランク数はMPI・初期状態準備より前に拒否します。高速HSEは `(1,2)` を宣言します。宣言しない自作の計算コードは既存のexecution・分割検査を使います。この属性は数値精度・再開機能の認証ではなく、直接ResponseSessionへ接続する場合にも、同じ検査と宣言のランク間照合を物質準備前に行います。

ID付き直接保存の既定manifestは`salmonpy.native-direct/3`で、従来の/2と共通の互換情報として、保存方式、save/restore対応、各MPI群の所有ランク・点ID、場の分割と電子状態のk／軌道／実空間分割を記録します。全ランクで現在の状態と照合してからLOADを呼ぶため、総ランク数だけが同じ分割変更も拒否します。初期資源の作成は検査前に行いますが、検査中の伝播・snapshot/restore/LOAD呼出はありません。旧manifest/1には必要な互換情報がないため新しい経路では復元を拒否します。旧保存データは対応する元の版で扱ってください。計算処理ペイロードの形式は変更していません。自作direct-state/1コールバックには、明示的なcheckpoint_format、checkpoint_modes（save/restoreのtuple）、checkpoint_decomposition（群サイズを積に持つ正の整数tuple）が必要です。宣言は利用者の仕様であり、その実装・失敗時の原子的復元を認証するものではありません。単にsnapshotメソッドがあるだけでは直接再開と判定せず、同梱LD/SBE以外の再生方式を混入させません。

保存対応の宣言とMPI互換性の照合は共通API `salmonpy.checkpointing` を使います。自作の計算コードや直列呼び出し元プログラムからの利用は[CHECKPOINTING.md](CHECKPOINTING.md)を参照してください。既存の計算処理-direct/2の記録形式と再開経路は維持します。

計算処理混在サンプルの場・電子・LD/SBE保存処理も `CheckpointTarget`／`execute_checkpoint` を通します。保存形式と計算処理-direct/2の互換情報は維持し、コールバック失敗を共有した後は次の処理へ進みません。完了情報の公開失敗も全ランクへ通知します。

通常サンプルの`--direct-resume`は失敗時に元の状態を保つ復元が既定です。場内LD・SBE・Pythonから直接呼ぶTDDFT／高速PR HSEとPython側の時計・電流を、全群の候補成功後に反映します。古いABIと即時LOADのみの対象は読込前に拒否し、自動で従来方式へ切り替えません。通常サンプルは保護付き復元に統一しています。途中失敗からの継続・再試行と保証範囲は[CHECKPOINTING.md](CHECKPOINTING.md)を参照してください。

`--memory-budget-gib 4`は全MPIランク合計4GiBの助言予算です。通常状態と復元用の別状態の同時保持分を報告し、超過時も停止しません。[MEMORY.md](MEMORY.md)を参照してください。

## 混在サンプルのIDと再開

`identity.json`、通常実行の `result.json` と `point-response` アーカイブに同じ識別情報を引き継ぎます。直接保存の外側の形式は `salmonpy.native-direct/3`、再計算方式は `salmonpy.native-replay/2` です。数値状態の内部形式と更新順は変更しません。直接復元はIDとMPI分割を数値状態の読み込み前に照合し、保存時は全ランクでのID一致を検査します。

## Pythonから直接呼ぶTDDFTの更新前エラー拒否（限定対応）

新しく準備・ビルドした標準embedded TDDFTには `sp_tddft_error_protocol() == 1` があり、以下を結合先の物質MPI群だけで照合します。10: 不正・非有限入力／古いA／入力ファイル不在、11: ランク間不一致、12: 状態未作成・使用済み初期化、13: ステップ上限、14: 未確定の復元用の別状態あり。これらは数値更新前に全ランク同じコードで返り、既存の最後に成功した計算状態を変更しません。初期化前の10/11は初期化から終了までの期間を消費せず、Pythonからも入力を修正して初期化を再試行できます。失敗時の作業ディレクトリは診断用に残ります。

Pythonは版付きの仕様と全ランク一致を確認できた拒否だけを `InputError` とします。旧ライブラリ・未知のコード・非有限な戻り値は `RuntimeFailure` のままで、状態保持を推定しません。MPI群の全員が同じ入口へ参加する必要があります。無効なポインタ、MPI・プロセス異常、確保失敗は対象外です。本項の更新前検査ではソルバー深部を扱いません（次節の限定した深部復帰を参照）。初期化に入った後は引き続き1プロセス1初期化から終了までの期間です。高速HSEとPythonから直接呼ぶFDTDのエラー仕様はこの変更では拡張していません。

この保証は個別TDDFT状態の更新前拒否です。結合ドライバで他の部品が既に進んだ場合、全体の巻き戻しを保証せず、従来どおりセッションを失敗扱いにします。通常計算中の一般的な原子性が完成したとは判断しないでください。

## 大きなMacでの並列・格子テスト

4GiB・4コアの入門条件は、その条件での確認用として残します。大きなマシンでも利用者の実メモリ・コア数を確認し、OSや他の作業に余裕を残してください。64GB・18コアのMacでは、今回は48GiBを警告用予算として、最大15 MPIランク、各ランク1スレッドで測定します。これは推奨値の固定やハード制限ではありません。

`mpi_mixed_native` の `--field-shape 96 96 96` はFDTDの格子点数を変更します。各軸は40以上の偶数で、MPI分割に整合させます。既定値は40³のままで、格子間隔も2 bohrのままです。外側の真空領域が広がるため、異なる格子サイズを同一物理条件の比較に混ぜないでください。既定の物質点の物理座標は保ちます。電子状態のGS格子・k点は変更しないため、96³のTDDFT検証を意味しません。3Dは接続検証で、TDDFTの実用途は引き続き1D推奨です。

FDTD2＋SBE1＋TDDFT2は `mpiexec -n 5 ... --field-grid 1 2 1 --tddft-ranks 2`。FDTD12＋SBE1＋TDDFT2は `mpiexec -n 15 ... --field-grid 3 2 2 --field-shape 96 96 96 --tddft-ranks 2`。`...` には既存のPythonモジュール呼び出しとBUILD・RUNTIME・GS・新規出力先を入れます。`OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1` を指定してください。

ソース配布の `tools/test_mixed_scaling.py BUILD RUNTIME GS NEW_OUTPUT --rank-budget 18 --memory-budget-gib 48` は導入済みwheelを用い、同じ96³の入力で4/5/7/11/15ランクを順番に2回ずつ比較します。各計算のA/E/jを最初の計算と照合します。格子サイズが違う結果は比較拒否します。MPI実装固有の引数は `--launcher-arg` で指定し、計測中は他の重い処理を避けてください。

結果の `coupled_loop_seconds_max` は初期化・保存・直列参照計算を除いた時間発展区間です。通信計測には待ち時間が含まれ、純粋な通信帯域ではありません。FDTD内部のハロー通信は個別に分解していません。メモリは各ランクのピークRSSの和であり、同時刻の総常駐量や全システム使用量ではありません。時間・資源の計測失敗を計算失敗と混同しないでください。短い反復測定だけで一般的な並列効率や物理精度を保証しません。

## TDDFT深部の数値異常と直接巻き戻し

新しく準備・ビルドした標準Pythonから直接呼ぶTDDFTは `sp_tddft_recovery_protocol() == 1` を持ち、各ステップの数値状態をメモリへ退避します。伝播後の波動関数（20）、密度（21）、Hartree場（22）、XCポテンシャル／エネルギー（23）、電流／全エネルギー（24）を検査し、保護経路の伝播器エラー（25）も返します。検査は物質MPI群全体で合意してから戻ります。エラー時は波動関数・密度・場・伝播履歴・XC状態・カウンタ・管理フラグを最後に成功した計算状態へ直接戻し、伝播の再実行をしません。失敗したステップの通常RT出力も追加しません。

Pythonの `NativeTDDFTBackend` が返す状態の `advance(A_old,A_new)` は、版付き仕様と全ランク一致を確認できた復帰だけを `NumericalError` で通知します。`A` と `steps` はそのままで、原因を修正して同じ受理時刻から再試行できます。不正な波形を自動的に弱めたり、固定dtを変更したりしません。旧ライブラリや未知のエラーは `RuntimeFailure` の保守的な扱いを維持し、復帰を推定しません。

対象は周期・非スピン分極・固定イオン・中点伝播のPZ、TB-mBJ（自動／固定係数）、Libxc-PZ/PBEです。SOC、+U、jellium、イオン運動／力出力、Gram–Schmidt、projection/unfold、microscopic Maxwell結合などの保護対象外設定は更新前に15を返します。標準バッチ計算は従来の演算経路を使います。既存の外部checkpoint形式も変更しません。メモリ退避・有限性検査の費用が毎ステップ増えるため、資源見積もりには余裕を残してください。予算は警告のみです。

これはTDDFT群の状態保証です。FDTD・他の物質がすでに進んだ混在ステップ全体を自動巻き戻しする仕様ではありません。MPI／プロセス停止、確保失敗、未制御の外部ライブラリSTOP、初期化深部のSTOPや出力装置障害は未対応です。試験専用の一部ランク障害注入は `SALMONPY_RECOVERY_TESTING` を明示して別ビルドした場合のみで、本番ビルドには注入用C入口がありません。

## 高速PR版HSEの深部数値異常からの復帰

新しい `NativeFastHSEBackend` 用ライブラリは `sp_fast_hse_recovery_protocol() == 1` を宣言します。対応範囲は周期・非スピン分極・固定イオンの高速PR版HSE06、Taylor4／学習PT-CN、物質群内k点分割のMPI1／2です。通常版HSEへの切替はしません。

各ステップ前に電子状態とACE・因子／PT-CN履歴・交換キャッシュ・カウンタを退避します。FFTプランやMPIコミュニケータなどの所有資源はコピーしません。波動関数・密度・Hartree・XC・端点の有限性検査に加え、対応したACE演算エラー、PT-CNの収束／Gram／射影検査、履歴更新エラーを物質群全体で合意して返します。最後に成功した計算状態を直接戻し、過去ステップや交換履歴を再計算しません。失敗試行の通常RT出力を追加せず、A・時計・電流・エネルギーを維持します。診断ログは残ることがあります。

Pythonは宣言された版と全ランクの既知エラーを確認できる場合だけ `NumericalError` を返し、同じ受理時刻から修正した入力で再試行できます。旧ライブラリ・未知エラーは `RuntimeFailure` の保守的扱いを維持します。dtや入力振幅を自動変更しません。退避と検査のメモリ・時間費用は増え、予算超過は警告のみです。

これはHSE物質群の保証で、FDTDや他の物質を含む混在ステップ全体の自動巻戻しではありません。初期化深部、確保失敗、プロセス／MPI停止、未制御の外部STOP、出力装置障害は対象外です。異常を捕捉できない場合に継続を推定しないでください。

### 警告と実行エラーの区別

メモリ・ランク数の予算、推奨規模や物理精度の注意は警告として扱い、実行可能な計算を止めません。入力や刻み幅を自動変更しません。読み出せない・破損したファイル、配列寸法や実際のMPI分割の不整合、計算処理が停止する既知の未対応条件はエラーにします。未検証であることだけを理由に拒否しません。

高速PR入力検査では、有限な占有数の範囲逸脱や電子数との和の不一致は警告のみで、値を切り詰めたり再規格化したりしません。起動時の波動関数検査はバイト数の整合確認にとどめ、巨大ファイルの有限性全走査を毎回追加しません。そのためNaNを含む軌道を起動前に検出する保証はありません。旧GSヘッダーから物理的なGSの同一性を証明することもできません。

SCF未収束は警告のみです。有限な保存状態は後続計算に使え、`GroundStateResult.converged=False` と保存された残差・閾値・反復数で識別できます。

高速PRの計算処理起動前に、自動生成k格子と保持対称性の適合・代表点数・重み、物質種ごとの擬ポテンシャル参照、GSのヘッダー・占有数・軌道のバイト数を検査します。KYの検査は計算処理と同様に継続レコード・余分な末尾列・Eを省略した指数を扱います。他の認識済みPP形式は参照と読み出し可否までで、内容検査は計算処理に委ねます。対応GS形式は計算処理 endianの4バイトrecord marker・整数／論理値、binary64占有数、単一global real64／complex128軌道ファイルです。任意の `file_kw`、unfolding、偶数Gamma端点格子は現在の高速PR経路の制約です。GSを作ったMPIランク数と今回のランク数の一致は要求しません。直接RT checkpointの分割互換性検査とは別です。

高速PR版HSEの外場はCartesianの3成分A/cで、x・y・z・円偏光を固定z条件で制限しません。縮約k点では実際のAを各ステップで保持対称性と照合し、不適合なら状態変更前に拒否します。適合群がなければ全k点の初期状態を使います。新コアは一般セルの対称性付き初期化にも対応します。[対称性ガイド](FAST_HSE_SYMMETRY.md)を参照してください。

### 内部RT状態の所有分離（開発用）

失敗時に元の状態を保つ時間更新の数値退避・出力メタデータと直接復元用の別状態は、プロセス共通ではなく
各 `tddft_context` が所有します。同じ不変の物質入力とコミュニケータを使う、対称性なしの
内部高速PRコンテキストでは、一方の巻き戻し・候補の確定／取消・終了が他方の候補を
消費しません。個別に選んだdt・容量と3成分の波形で交互に進められます。
出力の再接続は空いている番号を取得し、巻き戻し中の状態を終了しても、他の状態が
再利用した出力番号を閉じません。

旧Python create_stateは引き続き1プロセスにつき初期化1回です。現在のCハンドルとPython open_modelは
この内部所有分離に接続します。SHARED_HSE.mdを参照してください。異なる入力のモデルを同じMPI群で扱う方法は[共有HSEガイド](SHARED_HSE.md#異なる入力のhseモデルを同一プロセスで扱う)に記載しています。任意のコミュニケータへの切り替えやスレッドからの同時呼び出しは対象外です。
対称性・初期化・I/O・タイマーの共有状態と、同期的な直列化処理の配列上限は今後の分離対象です。
コンテキスト全体や所有権を持つFFT／MPI／Libxcハンドルをコピーしないでください。
テキスト出力の巻き戻しは、呼び出し元プログラムで保存済みのファイル内容を戻してから再接続します。
数値チェックポイントだけではログを切り詰めません。

## 標準TDDFTの初期化時MPI資源の解放

明示的な新規ビルドで `sp_tddft_context_mpi_protocol()==1` を持つ標準計算プログラムは、
Pythonと同じプロセスで実行するTDDFTの初期化と初期電流評価で作ったコミュニケータを状態ごとに所有します。
終了時に未確定の数値復元用の別状態・保護用退避を破棄し、通信要求キャッシュとXC資源を処理してから
その状態の子コミュニケータを解放します。呼び出し元プログラムの親と所有者のない共通資源は元の所有者が
終了するまで維持します。保存形式・更新順は変更しません。**1プロセスにつき初期化1回**の

明示的なABI診断 `int sp_tddft_resources(int values[4])` は、追跡中の子の数、管理表の枠数、
未確定復元用の別状態の有無、生存TDDFT状態の有無を返します。メインスレッド・群内同順序で
呼びます。空き枠はdetachまで残ることがあり、子の数が0でも全MPI資源・プロセスメモリが

比較し、電流が一致しました。復元用の別状態を保持して終了しても、追跡中の子・候補・状態は0となり、
呼び出し元プログラムの集団通信は継続できます。全k点PBE／HSE／FDTD混在の直接再開と失敗時に元の状態を保つ復元の
再試行も確認しています。MPI・プロセス異常、初期化・確保失敗、異種入力の複数状態化は

MPIコンパイララッパーの内部でOpenMP対応コンパイラを選びます。内部のCコンパイラが
OpenMPに対応しない場合は、MPIのラッパー設定で対応するものを選択してからビルドし、
その設定もコマンドとともに記録します。ラッパー名だけでは内部コンパイラを特定できません。

標準TDDFTの明示的な共有モデルと複数点配置は [SHARED_TDDFT.md](SHARED_TDDFT.md) を参照。

異なる入力を同一プロセスで順次切り替える標準TDDFTは [TDDFT_REGISTRY.md](TDDFT_REGISTRY.md) を参照してください。

新規ビルドのdirectory scope3では、FDTDのE/H更新の初期化・更新・保存／復元・終了も呼び出し元プログラムの作業ディレクトリを変更しません。相対ファイルは各場状態の作業フォルダ基準、絶対パスは維持し、例外時にもパス範囲を解除します。scope1/2と旧計算プログラムは従来の切替を使います。数値更新順・保存形式は変更せず、メインスレッドでの逐次呼出しと各プロセスで場の初期化は1回までという制約は維持します。

標準Pythonから直接呼ぶTDDFTの終了は、状態が所有するRT出力と子コミュニケータだけを解放し、呼び出し元プログラムが開いた固定番号30のファイルを閉じません。新しい計算プログラムで修正済みです。既存バイナリを書き換えず、必要な場合は明示的に対応版を準備してください。一般のI/O異常復帰・スレッド同時実行を保証する変更ではありません。

新規計算プログラムでは、標準TDDFTと高速PR HSEの時間発展中も、初期化時に割り当てた状態のMPI所有範囲を有効にします。更新中に作られた子コミュニケータはその状態の終了で解放し、兄弟状態や呼び出し元プログラムが管理するMPIのものを解放しません。通常のMPI分割・呼出し方・数値保存形式は変更しません。初期化以外の全資源やMPI障害からの復帰、同時スレッド実行まで対応したという意味ではありません。

標準TDDFTの単一状態計算処理経路も、新規計算プログラムでは初期化・更新・終了のタイマーを状態専用に保持し、呼び出し元プログラム側の計測値を維持します。対応するlegacy timer protocol1があれば `state.timing_seconds` からrankローカルの完了区間を照会できます。数値保存形式に計測値は含めません。古い計算プログラムの通常計算は従来どおりで、新照会だけが対応版を必要とします。高速HSEの単一状態経路にも、対応する別のlegacy timer protocol1があります。

FDTDの入力・更新段階の有限値検査は、全要素を明示ループで走査し、IEEE問い合わせにスカラーだけを渡します。NaN・正負InfのMPI全体での拒否と、拒否時の状態保持は維持します。新しい閾値や停止条件は追加しません。GNU/Macで検証済みですが、今回Fujitsuコンパイルは未実施です。

新しいPythonから直接呼ぶFDTDのcloseは、未確定の復元用の別状態と保護ステップ用コピーを解放してから場を閉じます。途中終了では従来どおり最終スペクトル等の完走時解析を実行しません。数値更新・保存形式・既存closeの返却コードは維持します。内部診断 `sp_eh_resources(int flags[3])` は場・保護コピー・復元用の別状態の確保状態を返す読み取り専用入口で、総メモリ量やMPI資源の解放を示すものではありません。

R2対応のPythonから直接呼ぶFDTDでは、場の初期化・更新・終了中に生成する子コミュニケータを場の初期化から終了まで管理し、通信キャッシュを終了してから回収します。親MPI接続と別所有者の資源は維持します。任意の `sp_eh_mpi_resources(int values[3])` は接続内のlive子数・登録枠数・場の所有数を返す読み取り専用診断です。登録枠は再利用のため残るので、解放判定にはlive数を使います。MPI分割・場とLDの更新順・数値保存形式は変更しません。各プロセスで場の初期化は1回までという制約やMPI障害復帰の範囲も従来どおりです。

Pythonから直接呼ぶFDTDの初期化は、受付検査と数値初期化を区別します。新しい計算プログラムは、不正な点数、空・長すぎる・存在しない入力パス、および正常に解析できた未対応のtheory／再開設定を、数値初期化の使用済み状態にせず全ランクで拒否します。解析用の一時領域は呼び出しごとに保持します。空のコンテキスト確保やMPI所有者の受付に失敗した場合は、そのコンテキストを解放します。`eh_init`より前なら同じ接続で修正した計算処理呼び出しを再試行できます。Pythonコンストラクターの接続所有方針は変更しません。後述の検出済みパーサーエラーと初期化の早期パラメーターエラーも復帰対象です。それ以外の`eh_init`内部の失敗は対象外です。

新しいPythonから直接呼ぶFDTD計算プログラムでは、パーサーが検出したnamelist読み取りエラーはMPIを終了せず、全ランクで初期化失敗として返します。解析用の一時ファイルを閉じ、数値初期化前に修正した入力で再試行できます。単独実行の従来パーサーの失敗動作は維持します。対象は検出済みのnamelist読み取りエラーです。それより前の単位選択、座標解析、意味チェック、数値初期化には別の失敗経路が残ります。

Pythonから直接呼ぶFDTDでは、statusを返す解析経路で未対応の`unit_system`を指定した場合、MPIを停止せずstatus1001を返します。
Python側は受け付ける指定（`au`、`a.u.`、`A_eV_fs`）をエラーに示します。拒否前に解析用の一時ファイルを閉じ、
場の状態や子コミュニケータを残しません。任意statusを指定しない単独実行の従来動作は維持し、
有効な単位換算と数値更新順も変えません。座標・意味検査全体の異常復帰や、ジョブ入力の自動修正を保証するものではありません。

statusを返すPythonから直接呼ぶFDTDパーサーは、座標指定の競合・欠損（1002/1003）、孤立系での換算座標（1004）、
座標ファイルを開けない場合（1005）、行を読めない場合（1006）も区別します。rootランクの読込失敗は座標配列の通信前に共有し、
外部ファイルと解析用一時ファイルを閉じます。Python側も対応する原因を示します。既存の不正入力条件への対応で、物理条件の制限追加ではありません。
有効な座標の換算・処理順と、statusを指定しない単独実行の従来動作は維持します。メモリ確保、意味検査全体、任意の計算状態の初期化失敗までは対象にしません。
任意の静的検査ツールとは独立した実行時の異常処理です。

FDTDのE/H更新は実際に使用するy/nフラグ（周期・再開・形状／複製・場の観測／出力）を検証し、不正なら1013を返します。
大文字Y/Nを小文字として受け付ける従来動作は維持します。電子の伝播法・SCF・LCFOの選択肢一覧は計算処理 Maxwellの受付に適用せず、
未使用の電子設定の値で正常な場の計算を止めません。Maxwellが指定された電子計算法を実行する意味ではありません。
それ以前の共通パーサーと、実際のE/H数値初期化には別の検査が残り、未知のnamelistキーや不正な物理入力を何でも受け付ける保証ではありません。
statusなしの単独実行では既存の全体検査を維持します。

自作Python/Cカレント計算計算処理はSALMONの入力パーサーを通らず、内蔵計算法の名前一覧では制限しません。
明示登録した計算処理が独自パラメータの意味を扱い、SALMONpyは接続インターフェース・単位／時刻の仕様・返却配列の形と有限値を検査します。
独立した静的チェッカーも、未知の計算処理名やJSONパラメータは「未確認」とし、未対応として拒否したり、渡されたコードを実行したりしません。

FDTDのE/H更新では、入力読込中の電子計算専用前処理（KY擬ポテンシャル／スピン確認、EXX旧新MLWF設定の競合拒否、
EXXのk点アルゴリズム選択、ACE学習準備の検証・演算）も通しません。未使用の設定やファイルで場だけの初期化を妨げないためです。
入力の共有と場の単位・フラグの処理は残します。対象はstatusを返すMaxwell入力で、statusなしの単独実行や電子計算入力は従来の処理を維持します。
未知のnamelistキーや形式不正には対応するパーサーが必要であり、無視された電子計算法を場のソルバーが実行する意味ではありません。

新しいPythonから直接呼ぶFDTDでは、`eh_init`内の既存エラーのうち、格子指定の過不足（1101）、周期条件と境界の矛盾（1102）、時間指定の矛盾（1103）、CFL条件違反（1104）をMPI終了ではなく戻り値で返します。新しい停止条件は追加しません。失敗した場コンテキストを破棄し、既に格子通信を準備していれば通信キャッシュを先に解放してから、その場の子MPI資源を回収します。同じ計算処理接続で修正した呼び出しを再試行できます。Pythonコンストラクターの接続所有方針は変更しません。

MPI登録枠は再利用のため残る場合があります。失敗後の解放確認は生存数と場の所有数で行い、登録枠数ゼロを要求しません。statusを渡さない単独実行は従来の診断・終了動作を維持します。この対応は指定した早期エラーに限り、`eh_mpi_grid_sr`内部の後述の局所格子条件以外、後続の媒体・光源・入出力や一般の確保失敗、OOM、MPI障害からの復帰を保証しません。診断や計算を管理ノードで自動実行する仕組みではありません。

場用パーサーの選択は、`read_input(..., status=..., native_host=.true.)`で明示します。`status`だけでは、通常の入力前処理・検査を省略しません。`native_host`の既定値はfalseです。これはエラーを返すかどうかと、どの計算処理の設定を使うかを分けるためです。


## Pythonから直接呼ぶFDTDの担当領域に応じたJ配信

新しい計算プログラムでは、CoupledStepper／PacketCoupledStepperが初期化時に
`sp_eh_current_mask`で各場ランクの電流加算範囲を取得します。点の中心だけでなく、
その点の電流を加算するYee格子の辺を持つ全ランクへ、その点のJをScattervで配ります。
分割境界をまたぐ点は両側に配り、担当点がないランクへのJデータは0件です。
各点の3成分をまとめて配信し、不要成分まで個別に圧縮する方式ではありません。

場の代表ランクは従来どおり全点順序のJを保持し、出力と保存データを作ります。
他の場ランクの結合J配列は全点と同じ形を保ちますが、担当行だけが有効です。
全点の解析には代表の出力を使ってください。A・Eの観測値、Yee辺への重み付け、
E→LD→Hの更新順、異常時の合意・復元処理は変えません。

`sp_eh_step_owned`を備える計算プログラムは担当Jを直接受け取ります。
従来の`NativeEHField.advance(J)`は全ランク同一の全点Jを受け取る仕様を維持します。
対応ABIがない旧計算プログラム、Multiscale1D、単独のResponseSessionは従来の全点配信です。
ビルドは明示的に行い、import時や計算開始時に自動再ビルドしません。

保存形式とMPI分割の互換条件は変えません。同一の対応計算プログラムと分割で保存した
従来の全行Jデータも、復元後に担当行を選んで続行できます。異なるバイナリや
MPI分割のチェックを迂回する機能ではありません。各場ランクの担当行は
場manifestの`current_rows_by_field_rank`、配信方式は`current_routing`、
明示的な`communication_report()`のランク記録では`received_current_rows`で確認できます。
これらは論理的な点数であり、ネットワーク実測バイト数ではありません。


## 結合ステップの外側合意

通常のCoupledStepperは、場更新の結果とResponseSessionへの入力検査を一つの
合意にまとめます。隣接合意の統合段階では正常な1ステップの外側合意は4回から3回でした。
現在の標準経路は、後述のA/J同梱輸送でさらに削減しています。
同じ統合段階でPacketCoupledStepperはH不要なら7回から4回、Hが必要なら7回から5回でした。
ここでの1回は群内→群代表間→群内の階層合意であり、MPI呼び出し1回という意味
ではありません。初期化、計算処理内の検査・物理総和・近傍交換、点ごとの内部検査、
失敗時に元の状態を保つ時間更新の保存・復元合意はこの回数に含めません。通信時間短縮率も意味しません。

場の更新前の時計・使用可否検査と、物質更新後の合意は残します。Hを使う場合は
A/E採取の失敗を全群で合意してからH採取に入り、どこかが失敗したまま他のランク
だけがHの集団処理へ進むことを防ぎます。場・採取・パケット組立の異常は、
入力配信や物質コールバックより前に全群で拒否します。上流の異常は呼び出し引数で
受け渡し、次のステップへ残る共有フラグには保存しません。

単独のResponseSession.step／step_fieldsの呼び方は変えません。ResponseSessionの
公開stepを上書きした独自応答や、統合用hookのない独自responseオブジェクトでは、
従来の独立した合意と呼び出し順を保ちます。初期化時に一度だけ全群で方式を選び、
一ランクでも独自の入口を使う場合は全群が従来方式になります。応答入口の選択は
結合作成時に固定されます。自作物質計算処理の仕様も変えません。

通常のstepを新たに原子的にする機能ではありません。全体の状態保持・再試行には
従来どおり明示的なStepTargetを含む保護付き入口を使い、original_preservedと
cleanup_errorsを確認します。検証された例外復帰の範囲を、MPI停止・プロセス消失や
未対応計算処理異常からの復帰へ拡張するものではありません。


## A/Jと異常フラグを同じ通信で運ぶ

標準の結合入口では、A／場パケットとJの輸送ヘッダに、正常なら0、異常なら
通知元ランクの番号を載せます。数値Aは代表間のAlltoallvで各群の異常フラグと
担当点のAだけを交換します。場パケットは同じ役割のalltoallを使います。
Jは担当点の電流と異常フラグを一緒にGathervで回収し、場ランクへも
担当点Jと結果フラグを同じScattervで返します。

全群がフラグから異常を知った場合に限り、選ばれた通知元ランクをrootとして、
説明文を一回Bcastします。正常時に説明文をBcastする通信はありません。
Bcastに参加すべきことを先に全ランクが知っているため、正常ランクを別の処理へ
進ませたまま異常ランクだけがBcastする構成にはなりません。
異常が複数あれば、最小の通知元ランクを選びます。これは最初に通知する担当者で、
物理的な故障原因を一意に特定したという意味ではありません。

異常通知用のコミュニケータはParallelContext作成時に一度だけ複製し、終了時に
解放します。入力のMPI_COMM_WORLDを直接使わず、呼び出し元の通信領域を使える期間と
独立させます。正常ステップではこの専用領域に通信しません。import時にMPIを
初期化・複製することもありません。

独立した外側階層合意は、直前版に比べてA結合3→1、Hなしパケット4→2、
Hありパケット5→3です。代表間のPython MPI集団通信も、各々5→4、6→5、7→6
を実測しています。計算処理内部のMPI通信や保護付きトランザクションの通信は
この数に含みません。J回収後の短い結果通知は、離れた物質群にも確定・復元の
判断を知らせるため残します。正常時に通信がゼロになる意味ではありません。

`--ld-allocation-admission`は検証専用ビルドでのみ使用します。極配列の途中と
3D履歴配列の途中で一部ランクだけを失敗させ、解放と再試行を確認します。
通常版には障害注入を含めず、LD更新の演算順は維持します。
小さな材料一覧・係数一時配列、テンソル補助配列、subpixel専用の再配置、
PML・観測配列の確保失敗はこの対応に含めません。実際のOSメモリ枯渇や
強制終了、MPI障害からの回復を保証するものではありません。

### 材料・境界係数配列の確保失敗（1120）

計算状態の初期化では材料の誘電率・透磁率・伝導率（3配列）と、境界用E/H係数
（各軸、計6配列）もSTATで確保失敗を検出します。部分確保後に失敗した場合は
その段階の残りの確保を省き、FDTD担当群で合意して1120を返します。
材料係数を使う通信・係数設定や境界係数の初期化へ進む前に判定します。
所有状態と通信資源は解放し、全員一致の既知1120と復帰プロトコルを確認した
Python接続だけが再試行できます。材料配列の判定は既存のLD配列判定と共有します。LD使用時の追加通信は境界用の
担当群内1回（LD未使用時は材料・境界の2回）で、更新中は増えません。
予算超過は警告のままです。

PMLの大きな3D係数配列は1118の対象です。PML係数作成自体は既存配列を使い、
8層の小さな自動作業配列を持ちます。この自動領域や他の補助配列まで含めた
任意のメモリ不足からの復帰は保証しません。PMLの式・層数・更新順は変更しません。
検証専用の`--aux-allocation-admission`は、材料・境界の途中まで確保した後に
一部ランクだけを失敗させます。通常版には障害注入機能を含めません。

### 方向依存LD材料の初期化用メモリ

対角・非対角の誘電率テンソルを使うLD材料では、材料入力の保持に必要な配列も
Fortranの`STAT`で確保失敗を検出します。一部ランクで途中まで確保した後に失敗しても、
配列の配信前にFDTD担当群で1120を合意し、部分確保と通信資源を解放します。
Python側は初期化前の状態に戻り、メモリを解放した後に同じ入力で再試行できます。
入力ファイル自体の不正は従来どおり1110で区別します。

既存の初期化時の結果配信を担当群内の最大値集約に置き換えるため、通信回数は
増えません。時間更新の演算順・通信・保存形式は変更しません。メモリ予算超過は
警告のままで、ここで扱うのは実際に必要な配列を確保できなかった場合です。
OSによる強制終了や任意の作業配列の確保失敗まで回復できるという意味ではありません。

検証専用の`--material-allocation-failures`で、対角材料の途中、非対角テンソルと
極係数の途中をそれぞれ失敗させます。通常版には障害注入機能を含めません。

### LD更新係数を準備する配列の確保失敗

LD材料一覧、共通の更新係数6配列、方向別の更新係数3配列でも、Fortran側で
確保失敗を検出します。途中まで確保して失敗した場合は、その配列を使う係数計算や
LD状態の初期化へ進まず、FDTD担当群で1120を合意します。部分確保と担当する
通信資源を解放し、Pythonの初期化前の状態へ戻るため、メモリを解放した後に
同じ入力で再試行できます。実際に確保できなかった場合のエラーであり、
メモリ予算超過は引き続き警告だけです。

方向別係数は既存の結果配信を担当群内の最大値集約に置き換え、等方LDは
既存の材料配列の合意へ結果を載せます。初期化中・時間更新中とも通信回数は
増やしません。係数の式・計算順・時刻配置・保存形式は変更しません。
係数が非有限の場合の1111と、確保失敗の1120は区別します。

検証専用の`--ld-coefficient-allocation-failures`は、材料一覧、2D・1Dの共通係数、
方向別係数の途中で一部ランクを失敗させます。通常版には障害注入機能を含めません。
テンソル時間更新の作業配列、subpixel再配置、観測・画像用の作業配列や、
OSの強制終了・MPI故障からの回復まで保証するものではありません。

### 非対角誘電率に使う格子係数の確保失敗

非対角LDで使う格子ごとの結合重み・対角係数・材料番号の3配列も、確保失敗を
1120として扱います。確保だけを初期化の前半へ移し、値の初期化と係数計算は
元の位置・順序に保ちます。既存の材料配列の担当群内の合意より前に確保するため、
通信回数を増やさず、一部ランクの途中失敗でも配列を使う前に全員が戻れます。
部分確保した配列と担当する通信資源を解放し、Pythonの初期化前の状態を保つので、
メモリを解放した後に再試行できます。予算超過は警告のままです。

この変更は通常の非対角LDの格子係数が対象です。subpixel平滑化の配列は別に
確保しており、その処理や保証範囲を変更しません。時間更新の一時配列・観測や
画像の作業配列・OSによる強制終了・MPI故障は、この対応には含めません。
保存形式と係数の式は変更しません。

検証専用の`--tensor-grid-allocation-failures`で、5Dの結合重み、4Dの対角係数、
4Dの整数材料番号の確保をそれぞれ途中で失敗させます。通常版には障害注入機能を
含めません。

### 非対角LDの時間更新用作業配列

非対角LDの反復計算で使う大きな配列は、Fortranの更新呼び出しごとに最初に
確保し、反復の間は使い回します。作業領域はその呼び出しが所有し、物理状態・
保存データ・復元候補には含めません。subpixelで非対角結合がない場合は、
使わない結合用配列を確保しません。

Pythonから一ステップずつ呼ぶ場合、確保結果を既存の入力確認の担当群内通信へ
載せます。途中で失敗してもE/H・LD・時刻・出力を変更する前に全員が24で戻り、
途中まで確保した領域を解放します。Pythonは`RuntimeFailure`を返しますが、
`field.failed`は偽のままで、メモリを解放した後に同じJで再試行できます。
数値異常を表す`NumericalError`とは区別します。通信回数・係数の式・時間更新順・
保存形式は変更しません。メモリ予算超過は警告のままです。

対応するのは、明示的な時間更新用作業領域の確保失敗です。物理状態のバックアップ
作成やコンパイラー内部の一時領域を含む任意のメモリ不足、OSの強制終了、MPI故障
まで回復を保証しません。独立したSALMONプロセスでの計算は、確保失敗時に停止します。
画像・観測用配列の失敗処理を一律に広げる変更ではありません。

検証専用の`--tensor-workspace-failures`は、更新の最初・途中・後半で、駆動配列・
反復用配列・結合用配列を一部ランクだけ確保失敗にし、状態保持と再試行を調べます。
通常版には障害注入機能を含めません。

### 任意の観測点出力に失敗した場合

`obsN_at_point_rt.data`のヘッダーと時系列追記は、open・write・closeのI/O状態を
Fortran側で確認します。失敗しても場・LD・電子状態の更新は続け、
`SALMONPY_POINT_OUTPUT_WARNING`を出します。警告は状態・出力担当ランクごとに
最初の1回に抑え、失敗したopenのunitを閉じたり、呼び出し元のunitを変更したり
しません。この処理のためのMPI通信は追加しません。

次の観測時刻には同じファイルへの追記を再試行します。保存先の問題を直し、
必要なヘッダー付きファイルが存在すれば、その後の行を出力できます。
ヘッダー作成自体に失敗した場合、ヘッダー付きファイルの準備が必要です。
欠落した時刻の行や途中まで書かれた行は自動修復・再計算しません。
警告があった診断データは、不完全な可能性を確認してから解析してください。

この警告方針は観測点ヘッダーと時系列追記に限定します。面積分、情報ファイル、
再開データなど他の出力すべてを保護するものではありません。ファイルシステム全体の
障害や容量不足で他の必須出力も失敗する場合まで、計算継続を保証しません。
警告状態は物理チェックポイントの形式・数値には含めません。

### 任意の面積分出力に失敗した場合

`obsN_xy/yz/xz_integral_rt.data`のヘッダーと追記も、Fortran側でopen・write・closeの
状態を確認し、失敗時は`SALMONPY_PLANE_INTEGRAL_WARNING`を出して計算を続けます。
積分・単位換算・既存のMPI和通信は維持します。一つの面を書けなくても、後続の面や
他ランクの積分通信を省略しません。この処理による追加のMPI通信はありません。

警告状態は場の状態が所有し、最初の警告以降の繰り返し表示を抑えます。
保存先と必要なヘッダーを修復すれば、次の観測時刻から追記を再試行できます。
欠落・途中まで書かれた行は自動補完しないため、警告後の積分やエネルギー収支の
解析にはデータの完全性を確認してください。警告状態は物理チェックポイントの
形式・数値に含めません。呼び出し元が所有するファイルunitは変更しません。

これは面積分のヘッダーと時系列追記に限る対応です。面スナップショット、
周波数別の空間分布、情報ファイル、再開データ等の全出力は対象にしません。
従来のFortran呼び出しは維持し、`eh_save_plane_integral`の末尾に任意の警告状態を
渡せます。省略時も失敗は警告ですが、呼び出し間の警告抑制状態は保持しません。

### 終了時の観測情報ファイルに失敗した場合

アニメーション等で使う`obs0_info.data`も、Fortran側でopen・write・closeの状態を
確認します。失敗した場合は`SALMONPY_OBSERVATION_INFO_WARNING`を出し、計算済みの
物理結果を失敗扱いにせず、通常の状態・MPI資源の解放まで進みます。
既に保存した時系列やチェックポイントを削除せず、正常な情報ファイルの書式も維持します。
この処理のためのMPI通信や再計算は追加しません。

情報ファイルは省略・不完全な可能性があるため、警告後に可視化・解析で利用するときは
有無と内容を確認してください。終了後に自動的な再書き込みは行いません。
これは任意の観測情報ファイルに限定した対応で、必須の再開データの保存失敗まで
正常終了扱いに変更するものではありません。他の出力やファイルシステム全体の
障害も一括で保護するものではありません。

### 任意の面スナップショットに失敗した場合

`obsN_<成分>_<面>_<step>.data`の保存も、Fortranでopen・write・closeの状態を確認します。
失敗時は`SALMONPY_PLANE_SNAPSHOT_WARNING`を出し、他の面・成分と物理計算を続けます。
既存の面データ集約・単位換算・MPI通信順は維持し、書けないファイルがあっても
後続の集約を省略しません。作業配列の解放と正常な書式を維持し、追加通信はありません。
警告状態は場の状態が所有し、繰り返し表示を抑えます。

後続の観測時刻では、その時刻の別ファイルへの保存を通常どおり試みます。
欠落・途中までのファイルは自動修復しません。保存先を直し、チェックポイントから
利用者が同じ時刻まで計算を進めた場合は、その時刻のファイルを改めて保存できます。
復元そのものに再計算を追加する処理ではありません。警告後の可視化・解析では
ファイルの有無と完全性を確認してください。

この対応は時刻ごとの面スナップショットI/Oに限ります。集約用作業配列の確保失敗、
周波数別分布や必須の再開データ、ファイルシステム全体の障害までは保証しません。
従来のFortran呼び出しを維持し、`eh_save_plane`の末尾に任意の警告状態を渡せます。

### バッチ計算の周波数別面分布を保存できない場合

`obsN_eneM_<面>_with_wf/without_wf.data`のopen・write・closeもFortran側で確認します。
失敗した場合は`SALMONPY_FREQUENCY_MAP_WARNING`を出し、残りの窓関数・面・周波数と
終了処理へ進みます。既存のフーリエ蓄積・単位換算・MPI集約順を維持し、保存失敗を
理由に後続の集約を省略しません。追加のMPI通信や物理再計算はありません。
警告は終了処理内で最初の1回に抑え、開けた所有unitだけを閉じます。

対象はSALMON本体のバッチFDTD経路です。現在のFDTDのE/H更新結合APIがこの診断を
未対応として返す制限（15）は変更していません。周波数蓄積を持つFortran/Cで保持する計算状態の
保存／復元や保護付き更新を、今回対応したものとは扱わないでください。
失敗したファイルは欠落・不完全な可能性があり、自動補完や終了後の再試行はしません。
残りの出力を解析するときも周波数・面・窓関数の揃いを確認してください。
この対応は診断ファイルのI/Oに限り、蓄積・集約用配列の確保失敗やASE/ART等の
別出力、必須の再開データ保存、ファイルシステム全体の障害は対象外です。

### バッチLR・ASE・ARTの任意スペクトル出力

LRの時系列・応答表とASE/ARTのスペクトル表も、Fortranでopen・write・closeを確認し、
失敗時は`SALMONPY_OPTIONAL_SPECTRUM_WARNING`を出して残りの出力と終了処理を続けます。
ASE/ARTでは窓関数ごとにファイルunit・エラー状態・ファイル名を分け、一方を
保存できなくても他方の積分・MPI集約と出力を止めません。LRの時系列保存失敗でも
後続のフーリエ処理・応答表を省略しません。数値式・単位・正常な書式は維持します。
追加のMPI通信や物理再計算はなく、警告は終了処理内で繰り返し表示を抑えます。

対象はSALMON本体のバッチ経路です。FDTDのE/H更新結合の未対応診断に対する15の制限は
変更していません。欠落・途中までのスペクトルは自動補完せず、終了後の再試行も
しません。解析前に必要な時系列・周波数・窓関数の出力が揃っているか確認してください。
この方針は任意の診断出力に限り、必須の再開データ保存を黙って成功扱いにしたり、
配列確保やファイルシステム全体の障害からの復帰を保証したりするものではありません。

### 必須の計算処理チェックポイント保存に失敗した場合

`sp_eh_checkpoint(...,0)`は、任意の診断出力と異なり、保存失敗を非ゼロで返します。
既存ファイルを上書きしない`status='new'`を使い、いずれかの担当ランクでI/Oに
失敗すれば群全体で失敗を返します。保存は分離したデータを通して行い、実行中の
場・LD状態や時刻を更新しません。失敗を捕捉した呼び出し元プログラムは、保存先を修復するか
新しい保存先を選び、同じ状態から保存を再試行できます。成功扱いにしてはなりません。

低水準APIには複数ファイルの原子的公開はありません。他ランクが作った新規ファイルは、
全体として失敗した保存セットの一部であり、正式なチェックポイントとして使わないで
ください。既存の正式データは保持し、失敗試行のファイルは区別して別保管します。
再試行は新しい空の保存先が安全です。同じ低水準パスを再利用する場合も、正式な
既存データを削除・上書きせず、今回作成した試行ファイルと区別してください。
各ランクは異なるファイル名を渡し、上位層は全保存成功・整合性確認後だけ公開します。

実機では同一構成・MPI分割の通常状態で、既存ファイル・ディレクトリとの衝突と
存在しない親ディレクトリを一部ランクだけに与え、状態保持・修復後の保存・直接復元を
検証しています。元から備わる復帰処理を検証したもので、新しい保存形式や数値処理は
追加していません。ストリーム途中の容量不足・closeだけの失敗・プロセス/MPI障害や、
バッチの旧式`data_for_restart`保存すべての復帰を検証したものではありません。

### 旧バッチEM再開ファイルの保存

旧バッチの `data_for_restart` テキスト／バイナリ保存も、保存先を直接切り詰めず、隣接する `.salmonpy-pending` ファイルへ書きます。open・write・closeが成功した場合だけrenameで置き換えます。失敗したpendingは証拠として残します。修復して再試行するときは、該当pendingを別の場所へ移し、既存の正常データを保持してください。

内部Fortran保存ヘルパーの `io_status` は必須で、呼び出し側は保存フェーズ開始時に0にします。最初のエラーを保持し、そのランクの後続保存を行いません。初期メタデータ／各チェックポイントの保存フェーズごとに一度だけ、担当MPI群で失敗を合意します。必須保存の失敗はバッチを非ゼロ終了させ、保存成功とは報告しません。通常の時間ステップには新しい合意通信を追加しません。未公開APIのため、省略時の旧動作を再現する互換経路はありません。

これは各ファイルの段階保存です。バイナリ本体は付随情報の書き込み・closeが完了するまで公開しませんが、複数ファイル／全ランクの一括トランザクションやfsyncによる耐障害性は保証しません。保存フェーズの途中で失敗した一式は、以前と新しいファイルが混在し得るため、そのまま再開に使わないでください。直前に完成した再開ディレクトリは別に保持する運用が必要です。Pythonから直接呼ぶFDTDの独立候補による失敗時に元の状態を保つ復元とは別の経路です。

### バッチ再開ディレクトリの準備

`data_for_restart` が既存のディレクトリであれば成功コード0を返します。有効なディレクトリへのシンボリックリンクも利用できます。ディレクトリ作成失敗はrootだけで停止せず、従来の作成後バリアを担当MPI群の一度の状態合意へ置き換え、全担当ランクが非ゼロ終了します。衝突する既存ファイルやリンク先は変更しません。これは必須保存先の作成失敗の処理であり、既存ディレクトリの書き込み可能性を保証する事前検査ではありません。実際の書き込み失敗は各保存処理で検出します。通常ステップの通信と数値更新は変更していません。

### 旧バッチEM再開データの読込エラー

テキスト／実数・複素数バイナリの読込ヘルパーは、必須の `io_status` を返します。担当MPI群の全ランクが同じ順序で呼び、開始時に状態コードを0にしてください。open・read・closeを検査し、最初の失敗を保持します。ファイルは明示的に読み取り専用で開きます。共有ファイルでは状態コードを先に配り、失敗時に未読データのBcastへ進みません。ランク別ファイルは担当群で失敗を合意します。分割変更時は従来3回のメタデータBcastを状態コード付き1回へまとめ、作業配列割り当てとデータ読込も転送前に判定します。通常ステップへの通信追加はありません。

旧バッチ初期化は読込失敗を受けた直後に非ゼロ終了し、失敗した値を使って配列準備や時間更新を続けません。ヘルパーからはMPIと呼び出し元のファイルを維持して復帰でき、修復後に状態コードを0へ戻して再試行できます。ただし、失敗中の出力バッファや部分初期化済みモデルを有効な復元状態とみなしてはいけません。計算処理の独立候補による失敗時に元の状態を保つ復元とは別の仕様です。省略時の旧動作や互換フォールバックはありません。

`tools/test_em_restart_read.py BUILD_JSON NEW_OUTPUT --batch` はGSなしで欠損・切断・不正テキスト・ディレクトリ衝突と修復後再試行、実LD＋FDTDの途中再開を検証します。観測テキストの旧コピー処理は行末空白を落とすため、再開前の行の空白差は数値差と区別します。物理値やバイナリ再開データの差を許すものではありません。

入力と出力が同じ再開ディレクトリの場合も、必要な旧データをすべて読み終えるまで新しいMPI分割メタデータを書き出しません。読込失敗時は入力一式を維持します。読込成功後の保存までを含む全ファイルの一括トランザクションではないため、別に完了済みの再開ディレクトリを保持する運用は引き続き必要です。

## FDTD＋内蔵LDのパフォーマンスモード

同じ入力で通常モードの計算を確認した後、場のオブジェクト作成時に明示します。場の担当MPI群の全ランクで同じ値を指定してください。実行途中には変更しません。

```python
field = NativeEHField(
    context, calculation, build_record, work_directory,
    points=point_indices, grid=field_grid,
    execution_mode="performance",
)
A_next = field.advance(J_previous)  # 通常どおり電荷電流密度を渡す
```

既定の `execution_mode="checked"` は従来の経路です。`performance` は毎更新の全配列有限値走査、A/Jのランク間一致検査、検査だけのMPI合意、更新前状態の自動コピー・自動巻き戻しを省きます。空間分割に合わせた `advance_owned` にも適用します。Aの積分もFortranで行います。

初期化時の入力・MPI配置・型・時刻の検査、ビルド時の禁止ソルバー監査、既存ライブラリのSHA確認は維持します。更新中もポインタ境界や状態寿命の最低限のローカル検査、物理演算に必要なハロー通信・電場採取、テンソルソルバーの収束／破綻処理、指定された通常出力は残ります。電流の値・単位・所有者・呼出順の正しさは呼出元の責任です。

性能モードでは異常値をそのまま返す場合があり、内部ソルバーの異常でジョブ全体が終了する場合もあります。失敗時の元状態保持や、その場での再試行は保証しません。必要な保存点は明示的に作り、再起動できるようにしてください。明示的な保護付き更新・収支観測・保存／復元を呼べば、その処理自身の検査やコピーは実行します。自動で隠して無効化しません。

この指定が省略するのはFDTDとその内部LD更新の診断です。SBE／TDDFT／高速HSEの物質更新や結合ドライバ外側の検査は現時点では変更しません。計算全体が無検査になる指定ではありません。マニフェストの `execution_mode` で場の設定を確認できます。

開発用の `tools/test_diagonal_field_energy_mpi.py` も `--execution-mode performance` を受け付けます。収支観測を指定しない実測では `--observe` を付けません。ツールの最終保存・資源計測は開発検査の出力であり、性能モードの毎ステップ処理ではありません。新しい `sp_eh_step_performance` を含む場ライブラリを明示的に再ビルドしてください。

## TDDFTの性能モード

`NativeTDDFTBackend(..., execution_mode="performance")` は、呼び出し元が
MPIを管理する経路で検査を省く指定です。既定は `"checked"` で、
バックエンドと返される状態の設定は読み取り専用です。検証対象は周期系・固定
イオン・スカラーのPZ、TB-mBJ、Libxc-PZ/PBEで、全A/cを与える横波配置と
middlepoint時間発展です。単一状態・共有モデル・異なるモデルの登録に対応します。
別プロセス型・高速HSE・分子には未対応です。

初期化・ライブラリのSHA256照合・明示的な保存／復元は検査します。更新時は
Pythonの新旧A・有限値・一致の検査通信、作業ディレクトリの検査合意、Fortran
の引数合意・全状態退避・異常復帰用の数値走査を省きます。物理計算に必要な
通信と更新順は維持します。配列形状・容量・有効期間の境界検査はローカルに
残します。各ランクが有効で一致した呼び出しを行う責任は呼び出し元にあります。
非有限値は伝播し、Fortranの異常でMPIジョブが終了する場合もあります。戻り値
で更新失敗を検出した場合は、そのPython状態を失敗扱いにし、通常モードの
「状態を保持して再試行」の保証で続行しません。

明示的な電子数取得・観測・保護付き操作・出力には検査と負荷が残ります。
外側の結合ドライバーとFDTDは別の設定です。同梱例 `mpi_coupled_tddft` の
`--matter-execution-mode performance` はTDDFTだけを切り替えます。
C入口 `sp_tddft_step_performance(Aold,Anew,J_matter)` はSALMONの物質電流を
返し、Pythonで一度だけ電荷電流へ符号変換します。この経路のAoldはABI上の
引数で、前ステップとの一致は検査しません。

小さな合成GSを用い、4種類のXCそれぞれで内部1・2ランクを比較しました。
通常・性能・変更前ライブラリの電流と実測電子数が完全一致し、明示的な
メモリ内復元後も一致しました。実材料の収束や一般的な高速化の保証ではありません。

## 共有・登録TDDFTの状態ごとのモード

`NativeTDDFTBackend(..., shared_model=True, execution_mode="performance")`
または `registry_model=True` で、通常のセッションが作る状態の既定値を指定します。
モデルを直接使う場合は `model.new_state(point_id, execution_mode="checked")`
または `"performance"` で状態ごとに上書きできます。省略時はモデルの既定値を
使います。`registry.open_model(..., execution_mode=...)` で登録モデルごとの
既定値も選べます。作成後の状態の選択は読み取り専用で、他の状態とは独立です。
同じ登録管理器を再利用しても、前の物質設定のモードを引き継ぎません。

性能更新でもハンドルの世代・有効期間・容量・ABIの境界はローカルに検査します。
トークン・新旧A・モデル切替の診断合意、数値走査、自動退避を省きます。
モデル入力・作業領域の切替と物理計算に必要な通信は残します。通常モードの
状態は従来の集合的検査を維持します。明示的な保存／復元は検査し、復元先の
状態のモードを変えません。性能更新の失敗時に自動復元・再試行は保証しません。

合成入力で通常・性能状態の交互更新、独立実行との比較、4種類のXC、異なる
PZ↔TB-mBJ・Libxc-PZ↔PBEの登録切替を内部1・2ランクで確認しています。
実材料の収束検証や速度評価ではありません。

## 高速PR版HSEの性能モード

`NativeFastHSEBackend(..., execution_mode="performance")` は呼び出し元が
MPIを管理する更新を切り替えます。既定は `"checked"` です。
選択は状態ごとに固定されます。単一状態・共有モデル・異なるモデルの登録に
対応します。別プロセス型ワーカーには、この指定は未対応です。

新旧Aの合意、Pythonの有限値走査、電子状態・交換状態の自動退避、数値異常
復帰用の診断合意・走査を省きます。初期化・ライブラリ照合・ローカルな有効期間／
容量／形状・明示的な保存／復元・観測の検査は残ります。ソルバーの破綻判定、
FFT・Hartree・交換の計算に必要な通信、学習準備状態の通信も維持します。
縮約に残した対称性とAの整合条件は計算式の前提なので維持し、status34なら
更新前に拒否して有効なAで再試行できます。それ以外の更新失敗はPythonの
状態を失敗扱いとし、自動復元を保証しません。Fortranの異常でジョブが終了する
場合もあります。

学習用データを取り込む処理は、両モードでエネルギー・出力処理の前に保ちます。
状態が所有する一時フラグで処理順と異常復帰診断を分け、更新後に戻します。
プロセス共有の実行モード変数は増やしません。Taylor／PT-CN、全／縮約k点、
内部1／2ランクの合成入力で、電流・エネルギー・学習履歴とメモリ内復元後の
一致を確認しています。物理的収束や速度の評価ではありません。

`mpi_mixed_native --hse-execution-mode performance` は
`--fast-hse-mpi-build` を必要とし、HSE更新だけを
切り替えます。場と外側の結合処理は、それぞれの設定の検査を維持します。

## 共有・登録HSEの状態ごとのモード

バックエンドの `execution_mode` がモデルの既定値になります。
`model.new_state(point_id, execution_mode="checked")` または `"performance"`
で状態ごとに上書きし、省略時はモデルの既定値を使います。
`registry.open_model(..., execution_mode=...)` で登録モデルごとの既定値も
指定できます。セッションが登録管理器を再利用しても各物質設定の選択を維持します。
通常・性能の状態を混在でき、電子状態・交換資源・学習履歴・A／電流・出力履歴を
それぞれ保持します。プロセス共有のモード変数は追加しません。

性能更新でもハンドルの世代・有効期間の境界と、縮約対称性に関するAの数学的な
条件は維持します。診断用のトークン合意と自動復帰用コピーを省きます。
モデル入力・作業領域の切替、物理通信、学習処理順は維持します。通常モードの
状態は従来の検査・異常復帰経路を使います。明示的なメモリ／ディスク保存と
復元の検査・負荷は残り、復元先の状態のモードは変えません。性能更新の異常時に
自動復元を保証するものではありません。

`shared_fast_hse --execution-mode performance` はpoint-aを指定モード、
point-bを通常モードにし、point-aの再開も例示します。`--second-initial` を
指定すると、異なる入力モデルの登録を使います。通常の `mpi_mixed_native` の
`--hse-execution-mode performance` も共有HSE点に対応し、場・外側の結合検査は
それぞれの設定を維持します。

## 別プロセスの周期系TDDFT：性能モード

`TDDFTInitialState.new_state(..., execution_mode="performance")` または
`crystal.respond(initial, drive, execution_mode="performance")` でA駆動の
周期系ワーカーを切り替えます。`TDDFTResponseBackend(execution_mode=...)` も
応答セッションの各ワーカーへ選択を伝えます。外側セッション・場の検査は別設定
のままです。既定は `"checked"` で、状態ごとに固定されます。分子と高速HSEの
別プロセス型ワーカーは、この指定の対象ではありません。

ワーカーは専用の `INIT_PERFORMANCE` を受理し、
`SALMONPY_TDDFT_PERFORMANCE_V1` で応答する必要があります。古い実行
ファイルには自動で別の経路へ下げず、未対応を知らせます。モードはその子プロセス
の環境だけに渡し、Python本体の環境や同一プロセスで呼ぶ計算には設定しません。
初期化・実行ファイルのSHA256・通信形式／ステップ番号・容量・明示的出力の検査
は維持します。更新時のPython／ワーカーの入力・電流の有限値検査と、失敗後の
自動再起動・履歴再計算を省きます。失敗した性能ワーカーは閉じ、通常モードの
「状態を保って再試行」の保証で続行しません。物理計算・更新順・要求された電子数
出力・ソルバーの破綻処理は残します。新しい全体通信は加えません。

明示的な `snapshot()` / `restore()` と出力のため、受理済み履歴は保持します。
このワーカーの明示的restoreは、候補を起動して**保存履歴を再計算する方法**です。
波動関数内部状態の直接復元ではありません。snapshotの検査と再計算した電流の
比較は維持し、他方のモードで作ったsnapshotでも復元先のモードを保ちます。
明示的なsnapshot・出力保存では非有限値を検査します。GSコピーと整合性検査は
変更せず、この指定だけで起動時I/Oを減らすものではありません。

`tddft_response` と `mpi_tddft` の例は `--execution-mode performance` に
対応します。対応するワーカーを明示的にビルドまたは取得します。importでは
ビルドしません。
