# SALMONpyを使うAIへ

最初に読む文書はここだけです。機能ごとの詳細は、必要になった時に検索します。
初回の目標は **wheelを導入し、LDとSBEの短い計算を終えること** です。
DFT・TDDFT用の計算プログラムの構築や、全テストの実行を先に始めません。

## 既に利用している人への対応

導入と基本計算が確認済みなら、再インストール・quickstart・全テストを繰り返しません。[既存計算への追加](examples/README.md#add-to-existing)と、`python -m salmonpy.manual "既存の計算に機能を追加"`から始めます。
既存のモデル・保存GS・波形・出力先・計算プログラムを確認し、何を使い回し、何を変更するかを先に整理します。既知のメモリ・CPU・利用環境は再質問しません。新機能の追加依存と対応条件だけを調べ、必要なタスクの詳細を取得します。
新しい波形ならGSを再利用し、完全なSCF再開と初期推定の再利用、出力アーカイブとチェックポイントを混同しません。追加のビルド・ダウンロード・実計算は明示した操作に分けます。

## 利用者に何ができるか説明する

SALMONpyは、**物質の電子の応答と光の伝播を、単独でも組み合わせても使える計算部品集**です。
LDは軽い材料模型、SBEはバンド模型、DFT・TDDFTは第一原理計算、FDTDは電磁場の伝播を担当します。
入力準備や解析だけでも使え、自作の電流計算コードを接続することもできます。

| 利用者の目的 | 渡すもの → 得られるもの | 必要な準備 |
|---|---|---|
| 材料の誘電率・時間応答 | 材料係数・E → 誘電率テンソル・P・j | LDはwheelだけ |
| バンド模型で光励起を調べる | バンド・遷移行列・A/c → 電流・密度行列 | SBEはwheel。実材料のデータは別途必要 |
| 基底状態・力・バンドを求める | 原子配置・計算条件 → 保存GS・エネルギー・対応する力・バンド図 | DFT計算プログラムと擬ポテンシャル |
| レーザーで電子がどう動くか調べる | 保存GS・波形 → 電流、分子なら双極子 | TDDFT計算プログラムとGS |
| 構造中の光伝播・散乱を調べる | 構造・材料・光源 → E/H・反射・透過・エネルギー収支 | FDTD計算プログラム |
| 複合材料で光と電子を同時に解く | 材料の並び・厚み・各点の模型 → 相互作用する光と電流 | 対応する結合機能。TDDFTはまず1次元を推奨 |
| 計算の一工程だけを使う | 構造・波形・既存出力 → 入力準備・スペクトル・図・保存／再開 | 目的ごとの任意依存だけ |

説明はまず利用者の目的に関係する1〜2行に絞ります。初回はwheelだけで動くLD・合成SBEを試し、
DFT・TDDFT・FDTDの追加準備と混同しません。機械用の同じ説明は引数なしの `salmonpy.manual` が日英で返します。

## 追加入力なしの最初の計算

1. 使用するPythonと、OS・CPU・Python版が合う配布用wheelの所在を確認します。現在PyPI未公開です。配布先URLを推測しません。wheelがなければ所在だけを利用者に確認します。
2. 同じPython環境へ導入します。

   ```sh
   python -m pip install --only-binary=:all: "PATH_TO_COMPATIBLE_WHEEL.whl"
   python -m salmonpy.quickstart
   ```

   最初の引数は実際のwheelファイルへ置き換えます。NumPyが未導入でネット接続できない場合は、対応するNumPy wheelも管理ノード等で用意します。ソースビルドへ切り替えません。
3. `SALMONpy first calculations: PASS` と表示されたら完了です。表示された保存先の `summary.json`、LD/SBEログ、`sbe/` の結果を確認し、成功・実行時間・保存先を報告します。保存先は自動作成され、指定済みフォルダを上書きしません。永続保存先を選ぶ場合は `--output NEW_DIRECTORY` を使います。

計算は各1スレッドです。LDは1000更新、SBEは合成2バンド模型の500更新です。
Fortranコンパイラ、MPI、SALMON実行ファイル、擬ポテンシャル、基底状態は不要です。
数秒程度の実行を想定しますが、導入・取得時間を含む保証ではありません。
この例は導入確認であり、実物質の物性や収束を検証した結果ではありません。

Si固定入力例は、対応するApple Silicon用wheelとZIPを配布者から受け取った場合にSI_INTRO.mdへ進みます。入手済みの配布物と同梱の一覧の対応を確認します。擬ポテンシャルの取得は明示的な利用許可の後にPSEUDOPOTENTIALS.mdを使い、計算中には取得しません。量子キャビティ・量子計算機の別ブランチ／設計中の機能も、この配布版の実装済み機能として説明しません。

失敗時は最初に表示されたログを読みます。コンパイル・再ダウンロード・別汎関数への変更を無断で繰り返しません。
必要な時だけ `python -m salmonpy.doctor --json` で導入状態を調べます。
MatplotlibやASE等がないことは、この最初の計算の失敗ではありません。

## 次の計算を探す

```sh
python -m salmonpy.manual
python -m salmonpy.manual --lang en
python -m salmonpy.manual TDDFT
python -m salmonpy.manual "TDDFTとFDTDをつなぎたい"
python -m salmonpy.manual checkpoint
python -m salmonpy.manual --task checkpoint_compatibility
```

引数なしは用途の概要と初回手順、検索は上位5件の概要・API・必要な入力・対応条件・サンプル名を返します。`matches`は一致した総件数です。必要なら`--limit N`で表示件数を増やします。
検索結果からタスクIDを一つ選び、`--task TASK_ID`でそのタスクの詳細・実行例・指定言語のガイドを取得してから計算を組み立てます。未翻訳のタスクでは元ガイドを返し、`translation_available=False`と`instruction_language`で区別します。検索概要だけで対応条件を確定しません。
Pythonでは`search(query, lang="ja", limit=5)`、次に`task_details(task_id, lang="ja")`を呼びます。`load()`は全カタログを読む開発用の入口です。通常利用では全JSON・全ガイドを一度に読まず、検索と選択で必要な範囲を取得します。`manual.json`は機械用の検索データです。
人間には [README.md](README.md) / [README.en.md](README.en.md) を案内します。
過去の設計書・検証記録を現在の対応機能一覧として使いません。

## 研究計算の前に確認すること

- 既に回答された目的・総メモリ・CPU数は再利用し、不足分だけを聞きます。検出CPU数を全コア使用の許可とみなしません。見積もり・実測・不明を区別します。予算超過の見積もりは警告し、自動では止めません。
- DFT・TDDFT・FDTDは対応する追加の実行ファイルまたは共有ライブラリが必要です。ビルド済み配布物を優先し、利用者が明示的に選んだ時だけ同梱ソースを構築します。importはダウンロード・構築・MPI初期化を行いません。
- 管理ノードでは入力準備・任意の事前検査だけで終了します。検査成功から計算へ自動移行せず、計算はジョブ投入後にサイトの方法で起動します。MPIジョブ内で別のMPIランチャーを入れ子に起動しません。
- 混合率の既定値はPython/Fortranとも0.3です。明示された係数を優先します。SCF残差が振動して下がらない場合は、混合率を下げる試行を案内します。Broydenは`alpha_mb`、Pulayは`beta_p`、その他は`mixrate`で、`SCFSettings(mixing_rate=...)`が対応する係数を指定します。保持状態の`set_scf_mixing(...)`は履歴を保ちます。変更前後の残差を比較し、反復上限の増加だけで押し切らず、許容差を勝手に緩めません。自動低下は`SCFSettings(adaptive_mixing=True)`または保持状態の`set_scf_adaptive_mixing(...)`で明示的に有効化できます。既定は固定混合率で、自動増加・最適値探索はありません。
- SALMONの基本は基底状態の保存・再利用です。汎関数、擬ポテンシャル、セル、格子、k点を整合させます。SCF未収束なら残差の反復履歴を保存・図示し、警告とともに一旦止めて利用者の確認を待ちます。未収束を収束済みと説明しません。
- 格子収束は小さいk点数から開始し、擬ポテンシャル半径の約1/3を出発点にします。十分小さいdtで得た電流の相対誤差5%以下をスクリーニングの目安とし、確認できれば0.1Åまで細かくする必要はありません。dtは約0.2原子時間から縮め、数fsのインパルス応答と実測電子数を比較します。電子数減少率1e-5が目安です。NaN/Infが出た試行は直ちに止めます。目的別の精度は別途確認します。
- 資源計測の失敗と計算の失敗を分けます。RSS等を取得できなくても、計算が成功したなら「計測値不明」と報告します。未計測値を0で埋めず、計算の再実行を強制しません。

## 単位・状態・通信の約束

境界の数値は原子単位です。結晶はA/c駆動、分子の長さゲージはE駆動です。
返す電流は電荷電流密度jで、SALMON内部の物質電流Jとは `J = -j` の関係です。
二重に符号反転しません。結晶の通常の出発点は横波（transverse）です。
A/E/Hを取り違えず、接続ガイドの時間ステップ番号と更新順に従います。

各計算の状態を独立に所有します。保存・復元の可否、MPI分割との互換性、復元失敗時の状態保持はCHECKPOINTING.mdに従います。
解析用NPZを再開データと見なしません。性能モードは明示的に選び、検査・自動復元の省略範囲を説明します。
通常／性能モードで物理モデルを変えません。通信は所有するMPI群と必要な点に限定し、更新ごとの全体診断通信を追加しません。

## 実装・配布を変更する場合だけ読む

公開APIはAPI.mdと `salmonpy.api.PUBLIC_API` が基準です。数値計算はFortran/C、Pythonは入力・起動・記録を担当します。
「native」等の内部名で説明せず、実行ファイルを別プロセスで呼ぶのか、共有ライブラリを同じプロセスで呼ぶのかを明記します。API識別子・ファイル名はそのまま使います。

後方互換の分岐や暗黙の旧形式変換は追加しません。入力・保存形式・操作契約は該当ガイドの現行版を使います。
HSEの対応条件はSHARED_HSE.mdとFAST_HSE_SYMMETRY.mdで確認します。共有設定・作業ディレクトリを状態間で混ぜず、所有者を明示します。
NLCC付きの力やGPU等の対応範囲は使用する配布物の検証記録で確認し、未検証の機能を使えると説明しません。

新しい計算プログラムの構築前に、対象ソースを `tools/check_forbidden_eigensolvers.py` で検査し、リンクする全アプリケーションオブジェクトも検査します。
PZHEEVは照会も含め禁止、PZHEEVDは別の許可された手法です。構成・増分ビルドの監査を無効化しません。
変更していない検証済みプログラムの再利用時は、記録されたSHA256だけを照合し、実行開始時にソース・オブジェクト全体を再監査しません。
IEEEの有限性判定は要素ごとのスカラー呼出しを使います。計算記録の保存先は利用者・作業環境の指示を優先します。

CIはソース整合性、配布、短いAPI・合成模型の検査を自動実行します。全OS・Python版でwheelを構築し、全テストはOSごとの代表版へ集約します。
実材料の物理量再現・収束確認は自動必須CIへ追加しません。詳細はPACKAGING.mdを参照してください。

- SOCのSCFで整列用の補助磁場を使う場合は、`set_scf_spin_field`の原子単位とスピン寄与のみという範囲を確認します。既定ゼロ・任意機能です。各段階の残差とスピン磁気モーメントを確認し、最後は磁場ゼロで再収束させます。既存の磁化出力とμB単位の磁気モーメントを混同しません。

### 磁性体のSCF閾値

磁性体では `SCFSettings.for_magnetic(max_iterations=4000)` を明示的に選ぶと、残差の基準は `1e-5` です。`tolerance=` の明示値を優先します。一般の `SCFSettings()` は `1e-9` のままで、SOCだけを理由に磁性体と判断しません。残差に加えエネルギー・磁気モーメントの変化も確認します。振動が続く場合は混合率を段階的に下げますが、平均残差が下がり続ける場合は反復延長も検討します。Niの試験では最終無磁場の混合率0.15、観測間の変化1e-5 Ha・最大成分差1e-4 μBを目安とします。これは物理的な格子・k点・時間刻みの精度保証ではありません。

## 利用者への説明に含める情報

利用者には目的、必要な入力、得られる物理量、実行手順、対応条件を説明します。
実装の派生元、開発ブランチ名、過去の修正経緯、内部資源の管理方式は、通常の使い方案内には含めません。
HSEは「HSE」と呼び、開発ブランチ名・派生元・交換コアなどの内部区分を選ばせません。
API名・入力変数・ファイル名は実際の識別子をそのまま示します。
汎関数、スピン、ゲージ、MPI分割、外場と対称性の適合、保存／再開の条件は省略しません。
内部実装を変更する依頼では、docs/development/の資料を必要な範囲で参照します。
