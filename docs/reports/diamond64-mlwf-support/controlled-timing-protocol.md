# 負荷を確認した再計測

状態：2026-09-27、低負荷を待つ条件を撤廃し、全12回の逐次計測と数値一致検査を完了。RTのばらつきが事前基準を超えたため速度比は参考値。結果はreport.mdとcontrolled-timing-results.jsonに記載。

比較対象：beccb272（変更前）と19b9333c（変更後、FFT幅1）。実行ファイル、GS、原子配置、擬ポテンシャル、入力を同期対象外の/private/tmpへコピーし、180ファイルのSHA256を保存済み。

条件：Diamond C64/MPI8、C128/MPI16、core16³、R6、dt=.02、nt16、ACE1、OMP1/BLAS1。MPIはmap-by slot、bind-to none、oversubscribe禁止を明示。macOS/hwlocはCPU bindingをサポートしないため、コア固定の比較とは呼ばない。

測定順は旧→新と新→旧を交替し、各サイズ・各版3回、合計12実行を逐次実施する。中央値・最小最大・ペア比を保存。初回構築を除くWF／交換／ACEと後半の時間も保存。コードの性能比較には、RT時間の範囲が中央値の10%以内、未変更WF時間の前後中央値比0.8〜1.25という確認を用いる。これは統計的有意性の証明ではなく、大きな外乱を排除する条件。

開始時の背景負荷ゲートは100%→200%としたが成立しなかった。測定0件の時点で待機条件を撤廃し、通常の背景負荷下で旧版・新版を交互に逐次測定する。他のSALMONが存在する場合は開始しない。遅いWF/ACEフェーズを理由にデータを除外しない。600秒の実行上限は維持する。ほかのアプリの優先度や動作は変更していない。初回の8 MPIプロセスはnice=0を実測確認した。

実行中は2秒間隔でpsのCPU使用率を記録する。背景CPUの前後中央値差50ポイント以内も性能比較の安定性条件に加える。CPU100%は概ね1コア分だが、psの値は厳密な区間CPU時間ではなく診断用の指標。

電流・密度・出力エネルギー・初期MLWF・35回のACE構築を照合してから、ノートへ結果を追記する。安定性条件を満たさない場合も全12回の測定値を記載し、速度比を参考値とする。
