# Γ点実空間ACEの計量行列分散（2026-09-29）

通常GS／DC-LCFOから接続するnative Γ点の空間・軌道分割経路で、ACE計量行列と変換行列の全ランク複製を削減した。HSE06、PBE0、PBEhに共通で、交換の切断条件、MLWF半径、占有数、汎関数は変更しない。

## 処理と使用条件

ScaLAPACK有効かつ空間×軌道の合計ランク数が2以上なら、自動的に分散経路を使う。入力変数の追加はない。1ランクまたはScaLAPACK無効では従来のLAPACK経路を使う。

- `M=-dv U†W`を列単位で計算し、2次元ブロック巡回分散の担当部分だけ保存する。
- Hermitian性を分散転置で確認し、`PZHEEV`で対角化する。従来の正定値・条件数判定を維持する。
- 通常ACEでは分散変換から局所メッシュ上の因子を作り、変換行列は解放する。
- 局所支持ACEでは疎なWと分散した`A=V/sqrt(e)`を保持し、`-W A (A† W†ψ)`の順で作用させる。逆行列`A A†`は明示的に作らない。
- BLACSコンテキストは構築中のみ保持する。ACE状態のコピーに共有コンテキストの所有権は持たせない。通信は既存の空間×軌道コミュニケータを借用するため、その寿命はACE状態より長い必要がある。

## メモリ

占有／訓練軌道数をN、空間×軌道ランク数をPとする。この変更対象の密行列は、各ランクの`O(N²)`からおおむね`O(N²/P)`になる。通信バッファと固有値には`O(N)`が残る。小さい行列ではブロック割当・パディングの影響がある。

合成試験で実際に確保された**保持変換行列のみ**の最大バイト数：

| N | P | 従来（各ランク） | 分散後（最大ランク） |
|---:|---:|---:|---:|
| 128 | 2 | 262,144 | 131,072 |
| 128 | 4 | 262,144 | 65,536 |
| 128 | 8 | 262,144 | 32,768 |
| 65 | 8 | 67,600 | 8,976 |

この表はRSSや全体ピークメモリの測定ではない。構築中の作業行列とScaLAPACK作業領域、メッシュ波動関数などは別に存在する。

## 検証

GNU Fortran / Open MPI / ScaLAPACK / OpenBLASによる手元CPU検証：

- MPI/ScaLAPACK有効ビルド、MPI・ScaLAPACKなしのHSE有効ビルド成功。
- N=2,7,65、MPI=1,2,3,4,8で空間／軌道／混合分割、dense／局所支持ACEを確認。さらにN=128、MPI=1,2,4,8を確認。
- 空担当領域、異なる作用先軌道数、ACEコピー後の元状態解放、ゼロ交換、条件数約5×10¹¹の対角例、非Hermitian・特異・非有限入力を確認。
- 従来経路との作用差は上記合成試験で最大約1.6×10⁻¹²。ScaLAPACKなしのフォールバックでも同じ試験が成功。
- HSE06/PBE0/PBEh(40)の短いimpulse RTで、denseと局所支持ACEの空間／軌道分割における電流・エネルギーが既存の許容値2×10⁻⁸以内で一致。関連する入力拒否試験を含め7試験成功。
- 既存の分散交換、ACE悪条件、Γ点局所化、交換対選別の回帰も成功。

手動実行例（MPI/HSE/ScaLAPACKビルドを指定）：

```sh
python3 testsuites/651_hybrid_exchange/metric/run.py --build /path/to/build
python3 testsuites/651_hybrid_exchange/metric/run.py --build /path/to/build --no-scalapack
```

`MPIFC`、`MPIEXEC`、`BLAS_LIBS`、`SCALAPACK_LIBS`でコンパイラ・リンク設定を指定できる。テストは現行ソースを境界検査付きで一時領域にコンパイルする。Fugaku/NVHPC/GPUでは今回の変更を未検証。

## 残る負担

MLWFのゲージ・リンク・SVD行列、`orbital_hermitian_action`の行列、LCFO関連の一時配列には引き続き削減余地がある。メッシュ波動関数自体も全体で`O(Ngrid N)`を要する。今回の変更でプログラム全体のメモリが線形化したとは言えない。

列／ベクトル単位の通信が増えるため、実系での速度改善は別に測定が必要。現段階では大規模SiのRSSや速度改善率は未測定。

追記：[実計算の速度・RSS比較](matrix-memory-tradeoff-ja.md)を受け、通常経路にはACEのみ分散を採用した。native Γ点MLWFの[分散実装](distributed-mlwf-memory-ja.md)は比較検証用に残し、通常計算では従来MLWF経路を使う。入力変更は不要。
