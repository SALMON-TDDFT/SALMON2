# EXX作業配列の寿命整理

2026-09-29。採用済みのACE分散＋従来MLWFを維持し、native Γ点の作業領域を再利用する。交換率・局在支持・対選別・MPI通信・計算式は変えない。

## 変更

- `target_work`をACE更新の`local`へ`move_alloc`で受け渡す。内容の一致判定で更新不要なら作業領域へ返す。
- 更新が必要なら、旧`cached_source`は一致判定直後に解放する。更新成功後に新しい`local`をキャッシュへ移す。
- `w`はMLWF更新後、交換作用を計算する直前まで確保しない。既存の`action_work`があれば再利用する。
- 通常RTでは更新後の`w`を`action_work`へ返す。DCでは必要な`cached_action`として保持する。
- 作用側は対象・作用の作業領域を個別に確保する。配列の片方だけが更新処理へ移った状態にも対応する。

配列間のポインタ別名は導入せず、所有権を移す。更新処理と作用処理が逐次実行される既存の構造を利用する。変更はnative Γ点refreshと共通の作業領域確保に限定する。

## LCFO再構成後の配列

`init_conventional_from_dcdft_complex`は、フラグメントの基底・係数と再構成作業領域を終了時に明示解放していた。実数の`init_conventional_from_dcdft`も同様。通常の実空間RT経路に不要なLCFO基底が残るという変更対象は、ここには見つからなかった。

別のLCFO基底RT経路は計算中も基底を必要とするため、この整理の対象にしない。再構成中の一時ピーク削減と、RT中の保持メモリ削減は区別する。
