# Experimental local-exchange cuFFT backend implementation plan

Goal: implement the user-approved optional Gamma compact-exchange GPU route,
keeping CPU as default and the existing generic accelerator guards unchanged.

Architecture: CPU pair selection, compact kernel construction and MPI tile
collection stay in place. A procedure callback receives a rank-owned batch of
compact targets, forms pair densities, performs double-complex cuFFT transforms,
multiplies the existing discrete kernel and accumulates exchange actions on the
GPU. Transfer once per batch; no per-transform host round trips. Full-grid
fallback, MLWF, ACE, rVV10 and generic SALMON propagation stay on CPU.

Tech stack: Fortran, OpenACC, NVHPC cuFFT module, existing FFTW and MPI wrappers.

User approved the staged backend design on 2026-09-29. This ARM Mac has no
nvfortran/NVIDIA device: GPU compilation, execution and speed remain unverified
until the supplied opt-in tests run on NVIDIA hardware.

1. Add USE_EXX_CUFFT (default OFF), require native HSE and NVHPC/PGI. Compile only
   exx_cufft.f90 with -acc and link -acc -cudalib=cufft; do not enable USE_OPENACC
   for the rest of SALMON. Disabled builds expose a rejecting stub.
2. Add exx_local_backend='cpu'/'cufft', exx_gpu_batch_size=8 through the complete
   namelist/default/broadcast/lowercase/log/validation framework. Only Gamma,
   adaptive local-support native hybrid SCF/fixed-ion RT; reject incompatible
   inputs and unavailable build. CPU remains default.
3. Add an optional local-batch callback with explicit plan-owned state, preserving
   standalone CPU modules. Group targets across MPI owners with bounded
   user-selected batch size, preserve zero/skip handling and collective failure.
4. Add cuFFT batch implementation and GPU-vs-FFTW tests. Exercise scheduler via
   CPU callback and stub/error guards locally. Run CPU regression and builds.
5. Document mixed CPU/GPU scope, device mapping, build/test instructions, expected
   transfers and unverified GPU status. Commit implementation and documentation.

## Verification results

- CPU MPI/HSE/Libxc/ScaLAPACK and non-MPI HSE builds succeeded.
- Existing CPU numbered cases 422–437: all 48 stages passed.
- Conventional RT/OpenMP regression plus new input/backend-stub checks:
  12 tests passed; GPU parity explicitly skipped.
- Final callback oracle: MPI1/2/4 passed for batch sizes 1/2/3/8, partial batches,
  skipped/zero targets, empty work, pair counters, and collective backend failure.
- The host fatal callback was injected on MPI rank 0 while rank 1 waited in a
  barrier: the complete two-rank job exited with an error, without timing out.
  The disabled-backend and invalid-input stub tests passed as well.
- CMake rejected USE_EXX_CUFFT with GNU before building dependencies. Explicit
  GPU-test request failed with the expected missing-NVHPC diagnostic; no CPU
  fallback was misreported as GPU verification.
- Independent review found and resolved a potential MPI hang after a fatal
  OpenACC allocation/init failure. Registration precedes the first OpenACC call;
  the callback uses MPI_Abort when MPI is active and never returns. No existing
  communication abort wrapper is available, so this callback calls MPI directly.
- Updated manual section parsed with docutils; whitespace checks passed.

GPU compilation, OpenACC callback registration in the actual runtime, numerical
parity on NVIDIA hardware, and performance remain unverified. Initial GPU calls
create/destroy a plan and transfer the filter per batch; plan/filter caching is
future work after hardware validation. CPU global FFT fallback remains possible
when compact support is not economical. No asymptotic or timing gain is claimed.
