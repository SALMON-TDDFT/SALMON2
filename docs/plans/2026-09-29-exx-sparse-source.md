# 交換用MLWFの支持点保存

承認済み設計：実時間波動関数とゲージ輸送用previousは維持し、既存の球状支持マスク適用後の交換用sourceだけを格子点番号・値・列オフセットで保存する。非ゼロ成分はすべて保持し、追加の閾値を導入しない。

- sparse orbital型を追加。ゼロ軌道・空ランク・不正なindex/NaNを検証する。
- spatial exchangeはsource列を支持点だけ通信し、1列を展開して既存FFT経路へ渡す。
- source ACEでは32対象ずつ展開し、training metricは疎な値から直接形成する。ScaLAPACKと従来LAPACKを両対応する。
- 旧密source、全支持、保護された軌道、フォールバックは維持する。
- native 13回帰、疎training metricの空ランク・分散試験、128 H2を1回測定。既存の同入力の計測と比較する。
- 全メッシュsourceの一時生成は局所化・支持球判定の間に残る。全体RSSや全波動関数の次数を線形化したと主張しない。

## 結果

支持点保存・疎な計量行列・ブロック展開を実装。数値差は丸め誤差の範囲だった。128 H₂の1回比較でRSSは2,917→3,013 MiB/ランク、時間は12.05→11.66秒/step。全体メモリ削減が得られなかったため、`use_sparse_source=.false.`を既定に戻し、比較用ビルドで有効化できる実験経路として保持する。詳細は`docs/exx-sparse-source-ja.md`。
