## 1. 方針（プロジェクト責任者の決定。変更しないこと）

SALMONpy は、DFT・TDDFT・FDTD とその周辺技術を、独立して使える部品に分けた集合とする。

1. **部品は単独で使える。** 他の部品の内部型、Fortran のモジュール変数、SALMON の入力ファイルの書式に依存しない。
2. **部品をつなぐのは入出力インターフェースだけ。** 「版付きのデータ（アーカイブ）」と「時間発展プロトコル（`step`）」の2種類で受け渡す。自由度を優先する。
3. **SALMON 本体とプログラムが違ってよい。** SALMON 本体はアルゴリズムの供給源であり、同期は求めない。SALMONpy 側の変更を SALMON 本体へ戻すこと（PR やマージ）はしない。
4. 正しさは、参照用の SALMON の結果と許容誤差内で一致する回帰テストで担保する。ビット一致は移行の確認にだけ使う。
5. 状態はすべて明示的なコンテキストに持たせる。1プロセスに複数のインスタンスを置けるようにすることが目標。
6. `step` が失敗したら状態は変えない（失敗は原子的）。

### 決定済みの事項

| # | 論点 | 決定 |
|---|---|---|
| 1 | GS などのアーカイブの形式 | **Zarr v3 互換のディレクトリ形式、無圧縮チャンク（`bytes` コーデック、little endian）＋ルートの `manifest.json`（スキーマ版・各チャンクの SHA256）**。Fortran から `access='stream'` で直接書ける。チャンクは「k 点1個 × 軌道ブロック」。初版は実空間で分割しない。HDF5 は任意の書き出しにとどめる。**まだ実装していない** |
| 2 | 部品の境界での電流 | **電荷電流密度 j** を受け渡す。部品の内部は SALMON の物質電流 J（= −j）を保持する。**実装済み** |
| 3 | 時刻配置 | 各部品が `salmonpy.time/1` で宣言し、結合する側が結合前に照合する。**実装済み** |
| 4 | 擬ポテンシャル | アーカイブには参照（ファイル名・SHA256・入手元）だけを入れる。利用者が許可した場合に限りダウンロードし、ハッシュを照合して使う。**まだ実装していない** |
| 5 | 初版の対象範囲 | 論文化した部分。**スピン non-collinear、DC 法、孤立系、力の計算とイオンの運動（Ehrenfest）を含める** |
| 6 | GPU（OpenACC） | 今後の課題。当面は対象外 |
| 7 | SALMON 本体との関係 | SALMONpy の変更は本体へ戻さない。本体のバグ修正をどう取り込むかは未定 |
| 8 | リポジトリと配布 | 独立リポジトリは保留。wheel では MPI、BLAS、LAPACK、Libxc は利用者の環境のものを使い、なければダウンロードしてインストールする |

## 3. 実装した内容

### 3.1 場の部品（`salmonpy/maxwell.py`）

場の部品は `step(j_n) → A_{n+1}` を実装する。物質の部品は `step(A_{n+1}) → j_{n+1}`（crystal プロトコル）。
`couple(matter, field_model, dt=, steps=, output_directory=None)` が両者を交互に呼ぶ。
順序は j_0 = 物質(A_0) → A_1 = 場(j_0) → j_1 = 物質(A_1) → … 。

| 部品 | SALMON での対応 | 要点 |
|---|---|---|
| `Transverse(external)` | `trans_longi='tr'` | A = A_ext |
| `Longitudinal(external)` | `trans_longi='lo'`（`rt/em_field.f90`） | A_ind(n+1) = 2A_ind(n) − A_ind(n−1) + 4π j(n) dt²。A_ind(0) = A_ind(1) = 0 |
| `ThinFilm(thickness, external, epsilon=(ε1, ε2))` | `trans_longi='2d'` | dA_ref/dt = r dA_ext/dt + 4π d j/(c(n1+n2))。SALMON と同じく 100 分割で積算 |
| `Multiscale1D(cells, spacing, vacuum, incident, boundaries)` | 多スケール計算、`fdtddim='1d'`（`maxwell/fdtd_weyl_gauge.f90`、`ms/main_ms.f90`） | Weyl ゲージ。セル i は x = i·h。入射波の事前充填は SALMON の `incident()` と同じ。境界は abc（Mur）、pec、periodic。x は伝播方向なので x 偏光の入射は拒否。c·dt ≤ h |

- SALMON と同様に、**t=0 の電流は場に戻さない**。
- 演算の順序は SALMON に合わせてある。光速は `SPEED_OF_LIGHT = 137.035999084`。
- 1D の格子全体の量は `state.grid_A` と `state.grid_E`（中心差分の E、時刻 (n−1)·dt）で参照できる。

### 3.2 時刻配置の宣言（`salmonpy/timing.py`、スキーマ `salmonpy.time/1`）

- `TimeSpec(dt, inputs, outputs, t0, clock_offset, history, integrator)` で宣言する。
  - 部品の n 番目の時刻は t0 + (n + clock_offset)·dt。
  - `offset` と `clock_offset` は 0 か ½ だけ（`Fraction` で厳密に比較する）。
- `InputPort(quantity, offset, sampling, lag, uses_t0)` と `OutputPort(quantity, offset, sampling, at_t0)` で各ポートを書く。
  - quantity は A、E、H、j、J_matter。
  - sampling は point、interval_average、centered_difference。
  - at_t0 は physical か zero。
- `check_loop(field_spec, matter_spec)` の規則：
  1. dt と t0 が一致する。
  2. 接続するポートどうしで、quantity・実効 offset・sampling が一致する。許す変換は J_matter → j（符号反転）だけ。
  3. ループの lag の合計が 1 以上（陽的に解ける）。
  4. 入力側が t=0 を使うなら、出力側の t=0 は physical。
- `matter_timing(state, dt)`：宣言のない部品には crystal の既定（入力 A、出力 j）を当て、`UserWarning` を出す。
- `charge_sign(spec)`：出力が j なら +1、J_matter なら −1。
- 宣言を返すのは、場の部品4種の `state.timing`、`SBEState.timing`、`TDDFTState.timing`、応答サービスの各状態（`material_response._response_timing`）、`NativeEHField.timing`。
- 宣言は `couple()` の結果の `.timing`、`crystal.respond` の結果の `.timing`、各出力アーカイブのメタデータ `timing` に残る。

### 3.3 電荷電流への移行（決定 #2）

- `crystal.respond`、`SBEState`、`TDDFTState` は電荷電流 j を返す。内部の J は `state.matter_current` で参照できる。
- アーカイブの電流配列は `current`（以前は `J` = 物質電流）。
- `material_response.TDDFTResponseBackend` は符号を反転しなくなった（`TDDFTState` がすでに j を返すため）。
- `embedded_tddft._NativeState` はネイティブの J を −J にして返す。境界での変換はこの1か所だけ。

### 3.4 E/H Yee 結合の宣言（`salmonpy/coupled.py`）

- `NativeEHField.timing`：入力 j は offset ½・lag 1・t=0 不使用。出力 A は offset ½。
- `CoupledStepper` は、全点の物質側の宣言を MPI（`context.leaders`）で集め、`ELECTRONIC_CLOCK_OFFSET = '1/2'` だけずらして照合する。食い違いがあれば最初のステップの前に拒否する。
- 照合結果は `stepper.timing` に入り、`examples/mpi_coupled_tddft.py` の `response.json` にも保存される。

### 3.5 ランタイムのパッチの修正

`runtime/patches/salmonpy-runtime.patch` の `src/rt/embedded_tddft.f90` に、132文字を超える行が3つあった。
継続行に分けて修正した（トークン列は不変）。パッチは固定コミットのきれいな作業ツリーから作り直し、
`runtime/source.json` の SHA256 を `0f9faa9d…f4ae7f` に更新した。

## 4. 守るべき規約

- 単位は原子単位、座標は実験室系。A は SALMON の `Ac = A/c`、E = −dAc/dt。
- 境界の電流は j。符号を二重に反転しない。新しい物質の部品は `timing` を実装し、出力を j と宣言する。
- 時刻の半ステップずれを黙って入れない。変換が必要なら、明示的なアダプター部品にする。
- import 時にコンパイルしない。生成物（`salmonpy/_native`、ビルド、GS、可視化データ）をコミットしない。
- 共有カーネル（`native/` と `runtime/source.json` の `shared_kernels`）はバイト一致を保つ。パッチを変えたら SHA256 を更新する。
- SALMON 本体の公開リポジトリに PR を出さない。

## 6. 作業中に見つけた落とし穴

- SALMON の `rt.data` の行は itt = 1..nt（最初の行が t = dt）。比較するときは時刻の列で合わせる。
- `film_thickness` と `epsilon_em` は `&maxwell` に書く（`&emfield` ではない）。
- 多スケール計算の入力検査は、古い変数 `nxvacl_m`/`nxvacr_m` を必須にしている（2 以上。エラーメッセージの不等号は逆）。対応は nxvac = (|nxvacl_m|+1, |nxvacr_m|)。
- `rt.data` の `Jm` は物質電流。j と比べるときは符号を反転する。
- `tools/package_salmon_runtime.py` が受け付けるのは `python -m salmonpy.runtime build` の出力だけ。引数は `BUILD/build BUILD/source`。Libxc を有効にした場合は `--license-dir` が必要。
- 宣言（`timing`）のないテスト用の部品では、`UserWarning` が出る（既定の経路を通すため、わざとそうしている）。

## 7. 次の作業（優先順）

設計の全体像：部品は「共通コア＋DFT＋RT＋maxwell」の Fortran ライブラリと、Python の部品で構成する。
固定版 upstream の規模は、TDDFT の依存範囲が 101 ファイル・約 5.9 万行、DFT が 108 ファイル、FDTD が 29 ファイル。

1. **Fortran ソースを SALMONpy に取り込む。**
   - **着手前に必要なこと**：ルートの `AGENTS.md` は「SALMON 本体の全ソースをこのリポジトリに戻さない」と定めている。この作業はそれと矛盾するので、プロジェクト責任者の承認を得て `AGENTS.md` を改訂してから始めること。承認されていない間は、2 以降を現行の「固定 upstream＋パッチ」方式の上で進める。
   - `runtime/` の「固定 upstream＋パッチ」方式と、本体とのバイト一致の検査をやめる。
   - 由来とライセンスの記録は残す。
   - 取り込んだ直後に、§5 の比較がビット一致することを確認する。
2. **GS アーカイブ v2（決定 #1・#4）。**
   - DFT が書き、TDDFT が直接読む。内容は格子、原子、格子点数、ステンシル次数、k 点（分数座標とデカルト座標、重み）、占有、固有値、XC、擬ポテンシャルの参照、軌道 u_nk（形 (nk, nbands, nspin, nz, ny, nx)、C 順。SALMON の `zwf(x,y,z,spin,io,ik)` と同じメモリ順）。
   - 初版の対象範囲（決定 #5）に合わせ、non-collinear の 2 成分スピノル、DC 法の断片ごとの配列、孤立系（k 点なし）、原子の速度と質量も含める。
   - 規格化は Σ|u|²·hvol = 1。占有はスピン非偏極で最大 2。
   - 読み込み時に SHA256、電子数、正規直交性、XC と擬ポテンシャルの一致を検査する。
3. **`rt_context` を独立させる。**
   - 作成・1ステップ・保存・破棄をハンドル式の C ABI で提供し、1プロセスに複数のインスタンスを置けるようにする。
   - 残る障害：並列のグローバル変数（`nproc_group_global` など）、固定のファイルユニット、`stop`（依存範囲で約 416 か所）、OpenACC の `save` キャッシュ。最後のものは対象外（決定 #6）。
   - 独立性テスト：同じ A を与えた 2 インスタンスが、別プロセスでの結果とビット一致すること。
4. **設定を構造体で渡す。** `salmon_global` への依存（TDDFT の依存範囲で 43 ファイル）を段階的に外し、namelist は設定構造体を作る入口に格下げする。
5. **力の計算とイオンの運動を入れたら、境界の j にイオンの電流を加える。** SALMON では j = −curr + curr_ion（`calc_current_ion` の注記）。
6. **時刻配置の宣言の拡張。** 場と物質で刻み幅が違う計算が必要になったら、「刻み幅の整数比」を項目に足す。

## 8. 現在 SALMONpy でできること・まだできないこと

- **できる**
  - LD、SBE（wheel に同梱）
  - TDDFT（外部の SALMON ワーカー、PZ・TB-mBJ・Libxc-PZ・Libxc-PBE、周期系、middlepoint）
  - FDTD（一括実行）、DFT、バンド計算
  - 場の部品 4 種と `couple`
  - E/H Yee 結合（実験的、1 群 1 点）
  - 分散応答サービス
- **まだできない**
  - 座標回転（`rmat_ms`）、背景誘電率のある 1D 媒質、2D/3D の Weyl 伝播、再開
  - 1 プロセスで複数の TDDFT インスタンスを持つこと（§7 の 3）
  - GS アーカイブ v2
